THEME

KAEL · HUMAN-CENTERED COLLABORATION

把一次对话，
变成可继续的协作。

Kael 用唯一工作项承载目标，用真实所有者保存事实，用验证证据约束结论。Agent 加速理解和执行，人始终拥有目标、授权与最终判断。

PUBLIC METHOD协作不是把决定交给 Agent。

它把来源、事实、推断、建议、决定和执行结果放回正确位置，让下一次 Session 可以从当前事实继续。

COLLABORATION ARCHITECTURE

一个目标，两个增益环，八个动作

点击任一节点查看它的责任、真实所有者和停止边界。流程可以反复迭代，但人的确认不会被 Agent 的建议替代。

01 · THE CONTRACT

Agent 加速执行，
人拥有判断。

高质量协作不是让 Agent 替人决定，而是让 Agent 更快回源、行动和验证，让人基于更完整的证据做选择。

NON-NEGOTIABLE目标、授权与最终判断始终属于人。

Agent 的推断、排序和方案必须保留自己的来源身份。

02 · ONE WORK ITEM

Session 会结束，
工作项必须能继续。

原始需求保存真实来源，需求说明要实现什么，方案记录关键取舍，执行保存动作，测试保存证据，产出指向最终交付。

SOURCE原始需求

保留提出者原话与授权。

INTENT需求

把目标整理成可验收要求。

DESIGN方案

说明取舍、代价、边界和回退。

EVIDENCE执行与测试

记录真实动作及其证明边界。

03 · IN-TASK LOOP

一次任务里，
理解也在增长。

每次验证都会暴露新的事实或偏差。Agent 将它们带回方案和实现，直到结果满足目标，或准确报告为什么还未完成。

GAIN LOOP回源 → 行动 → 验证 → 修正

局部成功不能覆盖失败；新证据必须改变下一步。

04 · CROSS-TASK LOOP

真正的复利，
发生在下一个任务。

确认后的结论写回真实所有者。未来任务重新读取它、应用它，并用新的反例或证据修正它，判断能力才会跨 Session 保留下来。

CALIBRATION LOOP证据 → 确认 → 写回 → 重读 → 修正

聊天记忆不是长期事实，稳定知识必须有准入边界。
