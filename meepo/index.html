01 · COMPOSITION

宿主负责装配，
不吞并产品。

Server 和 Desktop 是 B/S、C/S 的可执行组合根。它们拥有入口、资源与最终装配；公共层和产品 Agent 保持独立，不依赖宿主私有实现。

DEPENDENCY RULE依赖指向可复用层，最终装配留在边缘。

这让同一个产品 Agent 可以被不同宿主选择和验证。

02 · PRODUCTS

才是用户价值单元。

Nest Assistant、Codex 组合与 Workbench 已有当前模块；Creative Visual 代表垂直领域产品方向，但仍处于 Building。

03 · FRAMEWORK

共享运行能力，
不共享领域流程。

Application、Client、Infrastructure、Presentation 和 POC 形成公共 Agent Framework。它们提供端口、适配与编排骨架，但不替具体产品定义用户价值。

FRAMEWORK ROLE复用 Session、Context、能力端口与执行证据。

领域方法和产品流程仍属于产品 Agent。

04 · INCUBATION

候选能力先验证，
再决定是否独立。

Workspace、App Server、模型适配与孵化内核位于候选层。它们可以被产品消费，但迁入正式组件必须经过当前依赖与真实验证。

CANDIDATE ≠ CURRENT模块存在，不等于能力已经产品化。

依赖版本、classpath、装配和运行结果缺一不可。

05 · PRODUCT PATH

从候选能力，
到可签收的产品。

候选能力进入 Framework 端口，产品 Agent 组织领域流程，组合根完成宿主装配，真实运行和证据最终回到工作项与人的判断。

进入 Workbench 交互帮助 →

PRODUCTIZATION能力 → Framework → 产品 Agent → 宿主 → 证据

任何一层都不应冒充下一层已经完成。
