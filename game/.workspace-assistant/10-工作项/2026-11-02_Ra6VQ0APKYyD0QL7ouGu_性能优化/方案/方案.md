# 方案：DotaRogue 性能优化

## 目标结果

将 DotaRogue 的运行性能优化至：
- **桌面**：全程 60 FPS（16.67ms/帧）
- **移动**：前 15 波 60 FPS，后期 50+ FPS（20ms/帧）
- **加载时间**：桌面 < 3s，移动 4G < 5s
- **内存占用**：降低 40%+

## 范围与边界

### 范围内
- 优化战斗循环算法（碰撞检测、距离计算、数组操作）
- 优化资源加载策略（按需加载、缓存）
- 优化渲染管线（离屏缓存、批量绘制）
- 优化内存管理（对象池）

### 不做项
- 不改变游戏玩法、数值平衡、视觉风格
- 不引入新的外部依赖库（保持纯 Vanilla JS）
- 不破坏现有角色、装备、技能系统
- 不影响现有测试流程的可执行性

### 约束
- 必须通过现有验证：选择页进入、波次流程、暂停恢复、工作台演示
- 移动端优化不能损害桌面体验
- 保持代码可读性，复杂优化必须注释

## 系统上下文

### 当前机制
- **碰撞检测**：朴素 O(n²) 算法，每个子弹遍历所有敌人
- **资源加载**：预加载所有 9 个英雄的全部姿势（32MB）
- **距离计算**：每帧多处重复计算相同实体间距离
- **数组操作**：大量 filter/map/sort 链式调用创建临时数组
- **渲染**：静态地面每帧重绘，无层次缓存

### 目标机制
- **碰撞检测**：空间分区（Grid Hash），只检测相邻格子
- **资源加载**：按选中英雄加载，建立内存缓存池
- **距离计算**：每帧开始统一计算并缓存
- **数组操作**：热路径改为线性查找，引入对象池
- **渲染**：静态层离屏缓存，只在摄像机移动时更新

#### 1.1 距离计算缓存

**问题**：`distance(e, player)` 在多处重复调用

**方案**：
```javascript
// 在 updateCombat 开头统一计算
function cachEnemyDistances() {
  run.enemyDistanceCache = new Map();
  const p = run.player;
  for (const e of run.enemies) {
    if (!e.dead) {
      run.enemyDistanceCache.set(e, Math.hypot(e.x - p.x, e.y - p.y));
    }
  }
}

// 提供查询接口
function getCachedDistance(enemy) {
  return run.enemyDistanceCache.get(enemy) ?? Infinity;
}
```

**受影响文件**：
- `game.js`：`updateCombat()` 新增缓存步骤
- `game.js`：所有 `distance(e, run.player)` 改为 `getCachedDistance(e)`

**验证点**：
- 功能不变：装备范围检测、技能释放仍正确
- 性能提升：Chrome DevTools Performance 测量 `distance` 调用次数

#### 1.2 数组操作优化

**问题**：`filter().sort()[0]` 排序全部只取最小值

**方案**：
```javascript
// 反模式（当前）
const nearest = run.enemies
  .filter(e => !e.dead && distance(e, p) <= range)
  .sort((a, b) => distance(a, p) - distance(b, p))[0];

// 优化（线性查找最小）
let nearest = null;
let minDist = range;
for (const e of run.enemies) {
  if (e.dead) continue;
  const d = getCachedDistance(e);
  if (d <= minDist) {
    minDist = d;
    nearest = e;
  }
}
```

#### 2.1 空间分区系统

**问题**：O(n²) 碰撞检测

**方案**：网格空间哈希
```javascript
const SPATIAL_GRID_SIZE = 200; // 格子尺寸

class SpatialGrid {
  constructor() {
    this.grid = new Map(); // "x,y" -> entity[]
  }
  
  clear() {
    this.grid.clear();
  }
  
  insert(entity) {
    const key = this.getKey(entity.x, entity.y);
    if (!this.grid.has(key)) this.grid.set(key, []);
    this.grid.get(key).push(entity);
  }
  
  getNearby(x, y, radius) {
    const cells = [];
    const minX = Math.floor((x - radius) / SPATIAL_GRID_SIZE);
    const maxX = Math.floor((x + radius) / SPATIAL_GRID_SIZE);
    const minY = Math.floor((y - radius) / SPATIAL_GRID_SIZE);
    const maxY = Math.floor((y + radius) / SPATIAL_GRID_SIZE);
    
    for (let gx = minX; gx <= maxX; gx++) {
      for (let gy = minY; gy <= maxY; gy++) {
        const key = `${gx},${gy}`;
        if (this.grid.has(key)) {
          cells.push(...this.grid.get(key));
        }
      }
    }
    return cells;
  }
  
  getKey(x, y) {
    return `${Math.floor(x / SPATIAL_GRID_SIZE)},${Math.floor(y / SPATIAL_GRID_SIZE)}`;
  }
}

// 使用方式
run.spatialGrid = new SpatialGrid();

function updateCombat(dt) {
  // 每帧重建网格
  run.spatialGrid.clear();
  for (const e of run.enemies) {
    if (!e.dead) run.spatialGrid.insert(e);
  }
  
  // ... 其他更新
}

function updateBullets(dt) {
  for (const b of run.bullets) {
    // 只检测附近格子的敌人
    const candidates = run.spatialGrid.getNearby(b.x, b.y, 300);
    for (const e of candidates) {
      // 精确碰撞检测
    }
  }
}
```

#### 2.3 对象池

**问题**：子弹、特效频繁创建销毁

**方案**：
```javascript
class ObjectPool {
  constructor(factory, resetFn, initialSize = 50) {
    this.factory = factory;
    this.resetFn = resetFn;
    this.available = [];
    this.active = [];
    
    for (let i = 0; i < initialSize; i++) {
      this.available.push(factory());
    }
  }
  
  acquire() {
    let obj = this.available.pop();
    if (!obj) {
      obj = this.factory();
    }
    this.active.push(obj);
    return obj;
  }
  
  release(obj) {
    const idx = this.active.indexOf(obj);
    if (idx >= 0) {
      this.active.splice(idx, 1);
      this.resetFn(obj);
      this.available.push(obj);
    }
  }
}

// 使用示例
run.bulletPool = new ObjectPool(
  () => ({ x: 0, y: 0, vx: 0, vy: 0, life: 0, hit: new Set() }),
  (b) => { b.hit.clear(); }
);

function shootBullet(...) {
  const bullet = run.bulletPool.acquire();
  bullet.x = x;
  bullet.y = y;
  // ... 设置其他属性
  run.bullets.push(bullet);
}

function updateBullets(dt) {
  for (let i = run.bullets.length - 1; i >= 0; i--) {
    const b = run.bullets[i];
    if (b.life <= 0) {
      run.bulletPool.release(b);
      run.bullets.splice(i, 1);
    }
  }
}
```

## 核心技术决定

### 决定 1：使用网格而非四叉树

**理由**：
- 网格实现简单（50 行），四叉树复杂（200+ 行）
- DotaRogue 实体移动频繁，四叉树的插入/删除开销高
- 网格每帧重建成本低（O(n)），四叉树动态维护成本高

**不选四叉树**：除非后期测试证明网格不足，否则不引入复杂性

**改变条件**：实体数量超过 500 且分布极不均匀

### 决定 2：不引入外部库

**理由**：
- 保持项目轻量（当前纯 Vanilla JS）
- 避免学习曲线和版本依赖
- WebGL 库（PixiJS 2MB+）收益不明确

**代价**：部分优化需要手动实现

**改变条件**：Canvas 2D 证明无法达到性能目标

### 决定 3：阶段 1 优先于阶段 2

**理由**：
- 阶段 1 风险低、影响广、实现快
- 可以快速验证优化效果
- 为阶段 2 建立性能基准

**顺序**：距离缓存 > 数组优化 > 地面缓存 > 资源清理
