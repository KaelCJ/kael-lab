# 特效制作方法论

用于把“做一个火／冰／风／雷／暴击效果”转成可审阅、可接入、可复用的产物。约束与完成边界遵守[特效制作规范](特效制作规范.md)，整体造型和视觉判断沿用[游戏作图方法论](游戏作图方法论.md)。本方法从风样张、卡尔混沌之风接入、火样张及陨石组合复用提炼。风、陨石由预览与卡尔共同消费，火供独立预览及陨石组合使用；各自验证范围分别回源，样张结论不能替代真实技能或性能验收。

## 先定位当前目标

回读当前工作项、[通用战斗特效](通用战斗特效.md)、相关角色／装备规则和实际消费代码。明确这次交付是样张、旧效果打磨，还是战斗接入；已有等价工作项就继续，不为每张图片或每个调参动作重复立项。

写一句可观察目标，例如“约定的小尺寸下能看出气流绕中心向上卷动，暂停后可检查前后层次”。同步确定锚点、方向、范围、起止事件、持续时间和不能遮挡的信息。只预览时把未来消费者标为候选，不擅自添加伤害、控制或升级机制。

## 研究参考时拆解技术问题

优先查现有源码与 GitHub 开源实现，也可以采用许可明确的其他社区素材。按当前问题检索轨迹、粒子生命周期、离屏缓存、精灵帧或混合绘制，不以引擎名或演示炫目程度直接决定技术路线。

对少量有价值候选，分别回答：哪部分形状和运动可借鉴、具体代码在哪、依赖哪些状态或运行环境、代码与素材各是什么许可、提取最小机制需要什么适配。来源记录格式和准入条件由规范维护。静态站点能够完成目标时，继续用现有 Canvas／SVG／PNG；存在实测瓶颈再讨论其他方案。

StarDefender-Alpha 的参考是素材预栅格化、粒子寿命与生成预算；它没有现成龙卷风。本次风选择自行绘制形态和素材，保留参考的机制思路。这个取舍可复用，具体形状不能通用于全部元素。

## 先拆轮廓、运动和时间，再选素材

先做主体轮廓和主运动，用最少层次证明它表达了目标，再添加体积、碎屑、烟尘和光。单独观察每层及组合，找出哪一层承担辨识；关闭装饰后主体仍应清楚。前后分层适用于有体积的旋转或遮挡效果，不要求所有效果都做三维漏斗。

物体旋转时分别处理表面标记和照明。陨石让岩壳、裂缝随行程转动，光照保持屏幕方向，避免高光跟着裂缝转成贴纸；这一做法适用于约定光源不随物体旋转的情况，不强制所有特效采用同一照明方式。

时间可以按“出现／蓄势—主体／命中—消散”拆解；循环效果另定义循环接缝和外部停止后的收尾。阶段长短来自真实动作与玩法时机，不能让装饰收尾继续暗示已经结束的伤害。

替换已有技能表现前，先画出移动、伤害 tick 和寿命的既有时间线，再安排视觉阶段。陨石的短暂下落只改变绘制高度，原有移动和计时照常推进；视觉接地与首次伤害分别对齐，不为做落地动画改动玩法时序。

下表是设计问题与候选方向，**不是效果包的完成清单或固定美术配方**；各元素的当前状态以[通用战斗特效](通用战斗特效.md)为准：

| 效果 | 先验证的主要特征 | 可选补充 |
| --- | --- | --- |
| 火 | 向上拉伸与摆动的焰形、根部与尖端的差异、明暗脉动 | 火星、烟气；避免只画橙色圆点。 |
| 冰 | 有棱角的结晶或裂片、凝结／断裂节奏、清楚的作用位置 | 冷雾、细屑；减速持续时间仍由玩法传入。 |
| 风 | 有方向的流线、旋转或卷动、前后层次与循环连续性 | 碎叶、尘雾；并非所有风都要做龙卷。 |
| 雷 | 起点与命中点的连贯关系、折线或分叉、短促亮暗变化 | 接触火花；连锁目标与顺序来自真实判定。 |
| 暴击 | 命中瞬间的强调、方向及快速回落，与普通命中可区分 | 短亮闪、碎屑、数字／音效；与元素叠加时避免重复强调。 |

JS 适合随时间、方向和目标变化的路径；SVG 适合可编辑且清晰的形状；PNG 适合柔软、复杂或带透明渐变的纹理。可以只用其中一种，也可以组合。先证明当前画法可读，再决定是否需要帧动画或其他工具；不要为凑齐三种格式重复制作。

## 做一个可观察的最小样张

复用实际渲染模块接入预览，不另写一套看起来相似的演示。提供足以回答当前视觉问题的操作：播放／暂停／重播、实际尺寸与放大观察、深浅或任务相关衬底、必要的方向与强度。仅加入真实存在的参数；加载、失败和无 JavaScript 的信息也要可理解。 减少动态效果下，默认静止与用户显式播放须分别验证：按钮状态、时钟推进和实际画面一致，不能只切换播放文案而永久锁住绘制参数。

第二元素接入时，先复用时钟、衬底和观察操作，再按差异配置控件与尺寸。火没有风的旋向参数，因此切到火时隐藏并禁用旋向操作；主焰的观察高度与外围烟、光晕占用空间分别处理，不能直接套用风柱高度。预览的渐显与缩放包络仍由页面提供，战斗接入时另按真实事件确定起止。

检查缓存与异步选择时，连续操作“火→风→火”，核对较早请求不会覆盖当前选择；失败后切换另一效果，再重试失败项。当前预览控制器按元素保存加载 Promise，成功切换复用渲染器、失败清除对应缓存，并用选择版本忽略过期结果。本次真实入口已验证正常切换与缓存复用；延迟／失败／重试另用受控网络诊断验证，记录为补充检查，不能冒充自然异常端到端流程。

按顺序检查：先轮廓与锚点，再主运动与前后层次，随后命中／循环／收尾，最后加入装饰。火首版在真实截图暴露出所有路径同一水平线闭合造成的硬切根部，改为弧线收向脚点后复验通过；类似闭合轮廓应检查根部与落点连接，不靠增强光晕遮盖。实际尺寸看不清就回到轮廓与明暗，运动不明显就调整位移与节奏；不要用更多粒子掩盖主体问题。

暂停时检查重叠、透明边缘和裁切，连续播放时检查转向、闪烁、循环跳回及参数变化。实时改速度可能改变相位，应明确需要连续过渡还是允许重播；当前风的强度调整仍有相位跳变限制，不能当作已经解决的通用做法。

火把强度用于焰形和烟气等表现，不乘入时间，因此调强度不会按新流速重算相位。这个改进只适用于该参数；改变细节档位仍可能重新分布粒子，不能推断全部参数连续，也不改变风的已知限制。

## 接入一个真实事件，再验证复用

在任务授权包含战斗接入时，先选一个实际英雄、装备或敌人，梳理“游戏事件→表现实例／参数→绘制→结束清理”。一次命中只生成约定的表现，不能每帧重复生成；跟随目标的效果要明确目标消失、切波、死亡、重开时的行为。

让调用方提供玩法已确定的位置、路径、范围、进度或命中点。衔接相机、排序、前景遮挡和暂停；预览与战斗使用同一效果实现，但各自拥有场景与时钟。素材异步完成时，不把已经过期的事件重新播放出来。

线形区域须对照实际命中线核对中心、端点和朝向，区分“角色朝向”与“墙体延伸方向”；同一 angle 字段不保证几何一致。按主题检查绘制调用是否可达：角色技能放在两主题都调用的技能层，不能混入仅一个主题执行的地面纹理函数。卡尔冰墙与炽魂的复核暴露了这两类问题；修正绘制接线与方向时保留原命中、减速、寿命和召唤规则。

直立风柱随弹道飞行时，移动方向与形体朝向分别处理：脚点跟随玩法坐标，主体不套用普通飞弹的旋转。卡尔已采用这一接法；它只适用于需要保持直立的形体，不是所有飞行特效的规则。

滚动物体在移动处理前后取实际位置差，按约定旋向累计有符号行程，以行程驱动转角；火尾用实际位移方向。陨石由此在受阻时停止滚动、滑动时跟随实际方向。转向时保留已累计相位，只改变后续增量，避免用“总时间乘当前方向”让整个历史翻转。

组合特效优先复用已有渲染实现。陨石调用火渲染器表达火尾，但组合与独立火样张各自持有运行实例和缓存；复用成立不要求强行共享全局实例，记录真实的创建、缓存和释放责任即可。

第一个消费者稳定后，才检查第二个消费者有哪些相同参数、哪些专属语义。用真实差异决定接口，避免给所有效果塞入风的旋向或给普通命中加入无消费者的连锁配置。新增消费者时更新唯一当前契约和相应角色／装备的反向链接。

## 用真实流程决定是否交付

先记录本轮源码／资源版本、入口与期望结果，再执行规范中的验收范围。预览检查静态与动态形态；战斗检查真实触发、位置、范围提示、动作时机、遮挡、结束及业务结果。通过自动化操作真实入口可以替代人工点击，注入状态或直接调用绘制函数只能算补充检查。

固定脚点的陨石预览用虚拟行程方便观察滚动、火尾和左右方向；它不能证明技能确实移动、受地形阻挡或按时伤害。真实验证仍从选人开局，等待自然被动并操作主动回响，观察移动、结束及资源变化。

性能比较使用可说明的相同设备、场景、实例量与时长；先记录没有本次新增装饰或较低细节时的基线，再看目标配置。真实流程未到达密集场景时，把合成压力测试单列，不据此宣称长局通过。按规范保留关键形态和玩法信息，再降低装饰成本。

每个未通过项写清观察结果、原因所在层次和下一次验证动作。条件不具备就保存未覆盖项，不用旧截图、源图、代码扫描或演示 GIF 补成通过。

短寿命特效须在淡入之后、结束之前保留连续帧；触发瞬间的透明帧或结束后的空场景都不足以判断效果。验证暂停时，若场景另有环境动画，比较特效所在区域并记录区域边界，不能用全画布变化直接判定特效未暂停。素材请求失败时先确认实际显示的是新效果还是原有回退，再区分视觉验证与回退验证。

## 可复用的最小记录模板

以下内容放入已有工作项的需求、方案和测试记录，不强制新建一整套文件。当前 API 与消费者由[通用战斗特效](通用战斗特效.md)维护，模板只引用它，避免两处参数表长期漂移。

```text
效果 ID／本次目标：
交付阶段：设计、样张、战斗接入或新增消费者
真实事件与消费者；候选与不适用对象：
视觉目标：实际尺寸、锚点、方向、轮廓、主运动、起止与关键时刻
玩法边界：哪些数据由调用方提供；哪些信息不得被遮挡
来源：仓库／文件／固定版本或内容摘要、代码与素材许可、采用方式
实现选择：JS／SVG／PNG 的职责，可编辑源与运行输出，未采用方案的原因
当前契约链接：坐标、时间、参数、加载、结束及已知限制
成本目标：设备、实例量／触发频率、缓存、降级顺序、测量方法
验证记录：版本、真实入口与操作、期望／实际结果、截图或连续画面
结果分类：静态检查、视觉、交互、真实战斗、性能各自结论
未覆盖／失败／下一步：
可沉淀经验：适用条件、证据、反例或限制、应更新的长期文档
```

完成时回写当前状态、来源和真实消费者；将多次可用的约束更新到规范，将有效步骤与失败修正更新到方法论。首次经验必须写清适用条件，不直接升级为所有效果的固定参数。任务特定数字、截图和临时排障继续由契约或工作项拥有。

## 当前实例提供了哪些依据

| 本次观察或事实 | 可以复用的方法 | 仍不能据此推断 |
| --- | --- | --- |
| 同一渲染模块在预览和卡尔真实施法中组合程序化风柱、SVG 和 PNG | 按形态分配格式，让调用方管理时间和场景 | 其他效果也需要全部格式，或该 API 已适用所有战斗。 |
| 大图、约定小尺寸及三种衬底均有实际观察记录 | 在放大图之外检查真实尺寸和背景适应性 | 已完成地图遮挡、全部主题或真实手机验收。 |
| 暂停保持画面，恢复后变化；动态截图展示运动 | 分开验证静态层次与时间行为 | 已验证后台切窗、所有结束分支或连续变速。 |
| 采用缓存与有限粒子，运行中调强度仍可能跳变 | 明确工作量和参数连续性，并记录限制 | 已达到同屏、帧率或长局性能目标。 |
| 火以程序化焰形、PNG 烟和缓存光晕复用同页观察，指定桌面／移动模拟流程已验证，无 SVG 或旋向参数 | 复用职责与观察入口，素材格式和控件按实际能力取舍 | 其他元素都应采用这套组合，或仅凭独立样张就可确认战斗消费者通过。 |
| 火已复用预览时钟并保持粒子工作量有界，强度不改变时间相位 | 在第二元素中验证接口取舍，单独记录参数连续性 | 所有组合消费者的参数连续性和设备性能均已达标。 |
| 陨石组合火渲染实现，桌面与移动流程已确认自然被动及主动回响 | 先确认组合被真实事件消费，再分别检查位移、阶段、排序与暂停 | 暂停、换主题、地形和性能已全部验收；这些仍须逐项记录。 |

具体实现、已知限制及验证范围分别回源[通用战斗特效](通用战斗特效.md)和[游戏 README](../../README.md)。火的独立样张与陨石的组合消费分别保留证据；冰、雷、暴击及新增战斗消费者继续按任务核对，不沿用其他效果的验收结论。
