# 独立设计与预览

本文件维护 DotaRogue 五类内容的统一观察入口、正式数据所有权、运行复用与验收契约。具体英雄身份、装备数值、Buff 规则、特效参数及地图机制仍回源对应专题；本页不保存第二套内容定义。

## 当前状态

统一设计工作台当前可用，物理入口为 `game/static/dotarogue/studio.html`。已有 `game/static/dotarogue/effects.html` 的风、火和陨石样张继续可用；统一入口已完成既有范围的接线和真实浏览器验收；本轮灵魂守卫与 12 秒循环的接线、实际验证分别记录。受控场景仍不能证明自然对局已经获得物品或随机抽到技能。

英雄和地图定义此前从 `game.js` 原文提取为 `game/static/dotarogue/js/heroes.js`、`game/static/dotarogue/js/maps.js`，当时的语法、定义一致性与运行导入已检查。当前英雄目录为九名可玩英雄，包含灵魂守卫的双形态普攻及一主动一被动配置；四名未开放候选不进入演示目录。新增行为的验证边界以游戏 README 为准。

## 所有权与真实消费者

以下是本阶段已采用并核对的接线决定；新增消费者或破坏性变更须按本契约补充核对。

| 内容 | 正式事实源 | 预览与游戏的关系 |
| --- | --- | --- |
| 英雄 | `game/static/dotarogue/js/heroes.js` 的英雄、普攻、主动配置、三语文案、卡尔六项当前法术及灵魂守卫双形态攻击；`game/docs/characters/<id>/` 的设计、`game/docs/sources/characters/<id>/` 的来源与 `game/static/dotarogue/assets/characters/<id>/` 的发布资源 | 工作台读取正式目录；动作与技能演示复用游戏当前行为和绘制。候选英雄或已暂停的历史法术不能因进入设计资料就标为可玩／当前。 |
| 武器／装备 | `game/static/dotarogue/js/equipment.js`；[新增武器工作流](新增武器工作流.md)及[成品武器升阶设计](成品武器升阶设计.md) | 预览读取同一装备与强化定义，演示对应真实触发；英雄自带攻击与成品装备身份分开。图鉴仍负责完整配方和三级说明。 |
| Buff | `game/static/dotarogue/js/buffs.js`；[Buff 设计](Buff设计.md) | 常规属性使用现有计算，受伤、周期等使用相应事件。强袭与冰心的脚下光环由 `game.js` 的共享 `drawBuffAuras` 绘制，工作台和战斗复用；纯属性 Buff 仍不虚构独立动画，预览不修改品质抽取规则。 |
| 特效 | `game/static/dotarogue/js/effects/`、`game/static/dotarogue/assets/art/effects/`；[通用战斗特效](通用战斗特效.md) | 保留元素样张的独立观察语义；真实技能演示消费游戏事件及同一渲染器，不复制一份效果。 |
| 地图 | `game/static/dotarogue/js/maps.js` 的世界尺寸、地图与地形布局、曲线和 `buildTerrain`；[地图](地图.md) | 预览和游戏使用同一布局生成、绘制、碰撞与导航数据；不另画一张与实际地形无关的预览地图。 |

这些模块属于游戏内部，不上收到全站公共层，不为其他尚未实现的游戏预建注册表。常规游戏、统一工作台、元素样张和装备图鉴各自拥有界面与观察状态；共享内容的破坏性变更须同步当前消费者。

## 受控演示与正式游戏

工作台父页拥有分类、对象、动作选择和播放控件；嵌入同源 `game/static/dotarogue/index.html?studio=1`，由游戏内部的设计模式拥有演示局。两页用限定消息交互，父页不读取或任意改写游戏私有状态。当前消息协议为 `dotarogue-studio` → `dotarogue-runtime`：`init`、`select`、`play`、`replay`、`step`、`view`；运行页回传 `catalog`、`state`、`error`。字段由 `game/static/dotarogue/js/studio-runtime.js` 与工作台同源实现共同维护，父页只接收白名单目录和状态文本。

演示局复用正式初始化、技能、攻击、Buff／装备处理、时间更新与 Canvas 绘制，按当前选项布置有限目标及触发条件。它不推进正常敌潮、商店和战绩结算；重播或换对象时重建演示状态。播放、暂停、方向、主题是观察操作，不改变正式伤害、冷却和地形定义。

灵魂守卫的五个通用观察条目均已进入英雄目录；主动条目沿用正式 8 秒变身、被动条目沿用正式普攻蓄影与魔影出手。`game.js` 的 `studioCatalog()` 为英雄条目提供 `duration`：灵魂守卫为 12 秒，其余英雄为 8 秒；装备与 Buff 沿用 8 秒默认循环。`studio-runtime.js` 根据选中目录条目读取该值，到时重建演示局，父页消息不提供或覆盖时长。12 秒只延长观察循环，用于保留变身还原后的画面，不修改实际 8 秒变身或 24 秒主动冷却。

设计模式不写正常存档、设置或战绩。浏览器中的选择和播放不是仓库编辑器；正式修改由协作过程写入对应资源、配置或实现，重新加载消费者后使用同一结果。新增特殊行为仍需编码接线，不能由页面选择自动获得。

## 共同制作流程

1. 按对象读取现有专题及消费者，明确本次修改的是外观、参数还是玩法行为。
2. 在统一入口选择当前对象和适用动作，观察实际尺寸、方向、主题、暂停与连续运动；纯属性内容核对说明和属性结果。
3. 将已确认修改写入唯一正式事实源；不另存演示版数值或渲染实现。新增成品装备、角色和地图继续遵守各自完整交付规则。
4. 重新加载工作台，核对所改资源和代码确已加载，检查该对象及受影响的其他消费者。
5. 从 `game/static/index.html` 进入普通游戏，走真实选人、获取、施放、触发或通行链路，核对最终结果，分别记录预览与自然对局证据。
6. 把长期可复用经验和当前契约写回对应产品专题，把具体过程、失败、截图与未覆盖项写回工作项。

## 验证与状态边界

工作台是正式支持的设计预览功能，其真实入口与操作可以验收，但受控布置目标和触发场景不能证明自然对局已经获得物品或随机抽到技能。语法、定义一致性与资源检查也不能代替画面或实战。

状态按对象区分设计中、预览可用、游戏已接入、指定自然对局已验证。界面验收覆盖桌面、手机横竖屏模拟、键盘／触控、两主题、暂停恢复、减少动态效果、资源错误和无 JavaScript 基础说明；真实手机、全部组合和长局性能必须有独立证据。

前一构建已完成统一工作台实际接线与浏览器验收：8 英雄（当时含卡尔十法术变体）、38 装备、25 Buff、3 特效、3 地图；范围收缩后当前目录只保留卡尔六项法术；此前六法术构建已完成两主题、桌面／手机横竖屏的六项预览、键盘／触控、暂停／单步／重播复验。正常对局与观察页的验证结论分开记录，最新范围见[游戏 README](../../README.md)。真实手机硬件、Safari／Firefox、全部自然获取组合、密集同屏与长局性能仍未验证。四项暂停的历史法术不计入当前目录或验收矩阵。

本轮新增灵魂守卫的目录、双形态资源、技能读数和 12 秒观察循环已接线；其真实工作台与自然对局验证单独回源[游戏 README](../../README.md)，上述八英雄历史记录不作为本轮通过证据。
