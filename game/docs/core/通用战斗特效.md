## 魂之挽歌魂流（Current：源码接入，2026-10-30）

影魔主动技已由[requiem.js](../../static/dotarogue/js/effects/requiem.js)替换原来的三圈圆环与箭头，蓄力时六个小魂体向角色汇聚，释放后固定十八束直立的半透明灰绿魂体沿径向冲出，附带破碎烟流、轻微残影和细暗红丝线。魂体保持直立，拖尾沿径向展开，不把整张魂体随飞行方向旋转。形态参考经典实战图，由本仓库自行绘制；没有引入第三方模型、纹理、代码或新增 PNG。参考边界与缓存制作见[来源记录](../sources/art/effects/requiem/README.md)。

真实消费者为[game.js](../../static/dotarogue/js/game.js)中的影魔 Q，以及[统一工作台](../../static/dotarogue/studio.html)通过同一游戏宿主提供的影魔主动预览；独立元素页 `effects.html` 尚未加入本效果。普通与 DotA1 角色皮肤、工作台像素／初版观察均调用同一渲染器。源码接入不代表本轮实战、视觉矩阵或性能验证通过，实际完成范围待回写[游戏 README](../../README.md)。

### 渲染与生命周期契约

```js
const requiem = createRequiemRenderer();
requiem.draw(ctx, { cast, player, level: 1, reducedMotion: false, layer: 'back' });
requiem.draw(ctx, { cast, player, level: 1, reducedMotion: false, layer: 'front' });
```

- 坐标为游戏世界坐标，相机与 DPR 由宿主处理。`cast` 是既有施法状态；`delay > 0` 时读取 `player.x/y` 跟随角色，释放后读取固定的 `cast.x/y`。按径向的上下半圈拆分：`back` 进入地形之后、实体之前的技能地面层，`front` 进入实体之后、危险提示之前，两主题沿用相同顺序。
- 蓄力继续使用 `cast.delay` 的 0.55 秒。释放时以 `cast.age` 计算 `min(age / 0.55, 1) × 280` 的魂体脚点半径，与现有圆形伤害前沿一致；0.55 秒到达半径 280，随后 0.45 秒原地淡出，释放阶段共 1 秒。魂体上身与尾迹属于装饰外扩，不创建弹道实体、魂线碰撞或多次伤害。
- 施法状态、伤害、冷却和回收仍由战斗循环拥有。渲染器不持有独立施法列表、不推进时间，不使用私有 RAF、墙上时钟或战斗随机数；暂停由宿主停止 `delay/age` 推进，结束随既有状态清理。模块用 `save/restore` 恢复透明度、变换、混合及图像平滑，不清空宿主画布。
- 页面初始化时同步制作八张 `160×208` 透明 Canvas 魂体和一张 `96×96` 烟缓存，每页单个渲染器复用；离开对局不重新制作，页面销毁后释放。没有异步素材下载、资源失败重试或独立回退分支，也不要求运行时构建。
- `level` 按 Lv.1～4／5～9／10+ 分三档，只改变魂体尺寸、透明度和烟流局部厚度。十八束数量、圆形脚点半径和推进时间不随等级或魂数变化；原高等级同心环叠加已退出，避免两套轮廓竞争。
- `reducedMotion` 固定魂体帧和烟流摆动相位，移除跟随残影与烟团，将每束三层烟流降为一层，仍保留十八束及真实径向推进、淡出。普通状态每束最多三层烟流、三团缓存烟和一个跟随残影；蓄力只绘制六个小魂体。这是当前工作量边界，不是设备帧率或长局性能结论。

```text
python3 game/docs/sources/art/effects/wind/build_textures.py
python3 game/docs/sources/art/effects/fire/build_textures.py
```

## 武器羁绊与成长绘制（Current：2026-10-26源码接入）

`equipment-combat.js`拥有三新品及六羁绊的实际事件，工厂接收`getRun/passive/damageEnemy/blocked/pulse/isElite/heal/basicRange/label`，返回`onHit/onActive/onDamage/blockDamage/syncLoadout/update`。宿主连接有效普攻、成功Q、实际失血、最终正伤与战斗dt。切装调用syncLoadout，不带回移除后的圣盾；暂停和商店不充能。数值归[装备逐件设计](装备逐件设计.md)。

`effects/weapon-builds.js`是原创纯Canvas绘制：`drawWeaponStrike(ctx,fx,progress,view)`完整绘制带weapon元数据的武器事件，`drawBuildFeedback`绘制风怒连线或在文字旁附加圣盾碎片、激励纹、吸血滴与顺劈记号；返回值表示是否已完整绘制，未消费的文字仍由宿主显示。fx使用世界坐标、秒生命周期和0～1进度；width是实际判定全宽、r为实际落点半径，level是事件强化快照。陨星锤在结算后显示 0.42 秒后坐／落点冲击／碎裂，随后按等级显示 0.6／1／1.4 秒焦痕与余烬；事件总寿命为两段之和，不添加延迟命中或持续伤害。风杖与死灵书的阵列反馈由 `game.js` 消费同一事件。宿主应用相机/DPR/淡出，无独立状态／素材／伤害。减动效固定装饰相位，暂停由原事件life冻结，结束随原效果回收。

`effects/hero-growth.js`以`heroGrowthTier(level)`得到1～4／5～9／10+档。`drawHeroGrowthAreas(ctx,{hero,level,player,skills,time,pixel,reducedMotion})`在两主题共用技能层增强已有持续状态；`drawHeroGrowthEffect(ctx,fx,progress,view)`完整替代高档针刺、雷击、月光、火枪口与EMP；`drawHeroGrowthProjectile(ctx,projectile,view)`在弹丸本地坐标补内纹；`drawHeroGrowthKaelBody(ctx,spell,object,view)`在风／陨石原主体后加结构。短事件和射弹优先用heroGrowthTier快照，持续状态读当前等级；没有新增命中、个数、伤害、冷却或战斗随机。九英雄的消费者位于game.js，工作台通过同一宿主间接消费，观察档映射 Lv.1／5／10 同时显示技能倍率；自然局等级与工作台受控演示分开记录。

新绘制不清屏，save/restore保护透明度、坐标与线型，无独立时钟或每帧随机。减动效停止新装饰摆动，保留命中轮廓；宿主每帧最多24个短暂强调，超额回退简化反馈，陨星锤只保留落点椭圆；大数组装饰有24目标／24墙／2炽魂上限。未测密集长局帧耗时，预算不代表性能已验收。不引入外部代码；装备／Buff 图标按用户确认从 `game/static/dotarogue/assets/art/dota1/` 读取，战斗特效几何仍沿用确定性绘制、事件生命周期和有限预算思路；原三件 equipment-evolution 契约已扩展到全部 48 件成品，红杖、风杖、死灵书、陨星锤与陨星魔典的三级法术反馈通过已结算事件接入，新增游廊成品沿用对应事件与等级反馈。自然流程、受控工作台和隔离检查分别记录到游戏README。

## 特殊怪物与叠加状态反馈（Current：2026-10-27）

霜冻幽魂和雷霆蜥蜴由 `game.js` 的敌人循环拥有目标锁定、前摇、命中和清理；`drawEliteTelegraph` 绘制蓝圈霜爆与三叉雷带，`drawEliteSpellEffect` 在结算后补充冰环、中心闪光、雷击核心和落点火花。两种技能不在表现层重复伤害，暂停、死亡和回合结束沿用同一效果寿命。

## 装备形态绘制契约

消费者为 `game.js` 的角色前后层、装备效果和幻影弹绘制，工作台通过同一运行时间接消费；不是全站公共能力。`drawEvolutionEquipment(ctx, levels, view)` 使用角色局部坐标与三件最高等级；前层保留中央面部／躯干空区，共持时向外安排镜刃，红杖晶头保留在翼面外沿。`drawEvolutionCleave(ctx, fx, progress, view)` 与 `drawDagonFork(ctx, fx, progress, view)` 使用已结算的世界坐标、半径／角度和实际目标列表；`drawMirrorStrike(ctx, level, view)` 使用弹丸局部坐标与生成时等级快照。

调用者拥有变换、对局时间、0～1进度、主题与减动效设置；绘制恢复 Canvas 状态，无独立时钟、随机、伤害或装备状态读取。装备实体与完整弹丸形态独立于0.24秒出生特效；短时范围反馈沿用24对象／每件每秒六次预算，高攻速不保证每次独立闪光。减动效保留实体与实际攻击布局，停用新模块的装饰摆动与游走亮片。具体玩法和固定版本来源见[成品武器升阶设计](成品武器升阶设计.md)，真实验证边界见[游戏 README](../../README.md)。

## 风渲染器契约

稳定 ID 为 `wind`，入口为 [wind.js](../../static/dotarogue/js/effects/wind.js)：

```js
const wind = await createWindRenderer();
wind.draw(ctx, {
  x, y, time,
  scale: 1, intensity: 1, spin: 1, opacity: 1, detail: 1
});
```

- `ctx` 为 Canvas 2D 上下文；`x`、`y` 是当前坐标系中的风柱脚点，不是图片左上角。
- `time` 为调用者传入的秒数。渲染器没有独立时钟或每帧随机；相同参数重复绘制得到相同状态。调用者保持时间不变即可暂停，回到零可重新开始。
- `scale` 控制尺寸。默认风柱自脚点向上约 265 单位，外围尘雾另留空间；约 `0.34` 可观察 90px 高的风柱。预览页负责入场渐显与缩放，不由渲染器擅自结束效果。
- `intensity` 默认 `1`，内部限制在 `0.15–1.6`，改变宽度、轴线摆幅、粒子显著度及尘雾强度；小于等于零时不绘制。时间相位只由 `time` 驱动，运行中改变风力不会重算相位或造成位置跳变；风力连续过渡已在本轮预览复核，仍不等同于密集战斗性能通过。
- `spin` 以正负号选择相反旋向；`opacity` 为 `0–1`，并与调用者上下文透明度相乘。
- `detail` 为 `0–1`，上升粒子数从 36 调至 60，另有 12 个落脚尘雾；它不改变漏斗轮廓。

绘制保存并恢复上下文状态，不推进游戏时间，不修改玩家或敌人。螺旋路径采用有限采样，不使用每帧 `shadowBlur`。粒子数量上限与素材缓存是当前实现约束，**不是帧率或设备性能结论**。

战斗消费者决定事件触发、坐标、持续时间、冷却及结束清理；表现模块只负责绘制。改变脚点、时间单位、参数含义或素材路径时，须同步预览与战斗消费者、本专题及真实验证记录。

## 卡尔混沌之风接入契约

- 事件为 `castKaelSpell('tornado')`，被动万象轮转和主动回响使用同一分支。每次按 `kaelSpellRank` 生成 1～3 枚现有弹道，记录游戏时间 `startedAt` 与主动来源；主风对准 `768 + 敌人半径` 内最近有效敌人，额外两风分别偏转 `-.24`／`.24` 弧度，方向随后锁定，不追踪目标。
- `drawProjectiles()` 在通用弹道旋转变换前绘制，风柱始终直立，脚点与弹道世界坐标一致；相机与 DPR 由战斗画布负责，不在模块重复应用。旧的 500 单位紫色闪线已退出。
- 时间为 `run.totalTime - startedAt`，战斗尺度 `.72`（约 190 单位高），固定风力 1；前 0.06 秒淡入、最后 0.1 秒淡出，视口裁剪预留 220 单位以容纳风柱。独立元素预览的小尺寸仍约 90px。暂停不推进位移和内部运动；剩余寿命结束、穿透次数耗尽、出界或清空弹道时不再绘制。波末、重开和返回标题沿用原有生命周期，不保留独立风实例列表。
- 游戏页面预加载并缓存一个渲染器，离开对局仍复用该页缓存；素材尚未就绪或失败时沿用旧弹丸绘制，失败记录警告，不阻断战斗或补播已经结束的施法。
- 像素／初版共用此效果，局部图像平滑由模块恢复。普通细节为 50 个上升粒子与 12 个尘雾；减少动态效果时风柱仍按真实弹道移动，内部相位固定、粒子降至 36＋12。每次施法最多三实例，触发频率受 5 秒随机计时和基础 6 秒主动冷却限制，无新增同屏实例硬上限；未完成密集同屏性能测量。
- 2026-10-30 进一步放大并放慢：速度 240 单位／秒、寿命 3.2 秒，最长行程 768；扫掠命中半径 34，每风每敌一次、最多 8 次穿透、推离 34。原始每次伤害系数和原元素弹道地形规则保持，不新增吹起／悬空控制。2026-10-27统一伤害后，数量只随Kael的“攻击力”升级从1→2→3，装备／Buff攻击力不触发数量增加；伤害读取技能伤害，主动风命中时各应用一次技能成长和主动强化。

## 火渲染器契约（独立预览与陨石组合）

稳定 ID 为 `fire`，入口为 [fire.js](../../static/dotarogue/js/effects/fire.js)：

```js
const fire = await createFireRenderer();
fire.draw(ctx, { x, y, time, scale: 1, intensity: 1, opacity: 1, detail: 1 });
```

`x/y` 是火焰脚点，`time` 是调用方提供的秒数；同参数绘制确定，无独立 RAF、每帧随机或对局读取。`scale` 缩放整体，`opacity` 与调用者 alpha 相乘，绘制后恢复上下文。主焰约 240 单位高，含烟火星保守预留约 280 高、220 宽，脚点下另留柔光空间。独立预览以 `90/240` 作为小尺寸缩放基准，实际高度随脉动与火势变化；这一尺寸不直接作为陨石或其他技能的战斗尺度。

`intensity` 内部限制为 `.6–1.4`，调整形态幅度与烟透明度，不乘进时间相位；小于等于零不绘制。火没有旋向参数。`detail` 在 `.7` 以下将烟／离焰／火星从 8／4／16 降至 4／2／8，保留主体 13 条焰路径；切换细节会改变烟相位分布，未提供连续细节过渡。有限预算不等于已测帧率。

主体采用橙红外焰、金黄中层、淡黄内焰；焰舌弯曲向上传播，弧形焰根收拢于脚点，烟在后层膨胀淡出，少量火星上升并缩小。全部使用 `source-over`，不依赖强加亮混合获得辨识度。独立预览负责入场、暂停、重播和包络留白，按当前元素隐藏无效旋向控件。火模块不拥有命中、伤害或结束判定；陨石组合的方向、尺度与生命周期由下节消费者提供，其他火技能仍需单独确认事件。

## 陨石渲染器与预览契约

稳定 ID 为 `meteor`，入口为 [meteor.js](../../static/dotarogue/js/effects/meteor.js)：

```js
const meteor = await createMeteorRenderer();
meteor.draw(ctx, {
  x, y, time, angle: 0, travel: 0, lift: 0,
  scale: 1, opacity: 1, detail: 1
});
```

- `x/y` 是地面锚点；默认石头主体直径约 50 单位，中心位于脚点上方 24 单位。`scale` 缩放石头和火尾，相机与 DPR 仍由调用方负责。
- `time` 为调用方传入的秒数，只驱动火焰、火星、烟和裂缝亮度。`travel` 是调用方累计提供的有符号行程，模块以 `travel / 24` 计算岩壳与裂缝转角，不自行按时间推算移动；战斗传真实位移，预览传虚拟观察行程。主体光照保持屏幕方向，不随裂缝转动。
- `angle` 为运动方向弧度，火尾朝其反方向展开。`lift` 为调用方坐标单位的非负抬升量，不随 `scale` 再次放大；阴影留在地面，石头中心为 `y - 24 * scale - lift`。
- `opacity` 限制在 `0–1` 并与调用方透明度相乘；`detail` 传给火模块，低于 `.7` 时岩面细节从 6 处减为 3 处。绘制保存并恢复 Canvas 状态，不修改玩法或推进时钟。

陨石工厂创建一个火渲染器，复用其实现与烟 PNG，另缓存岩石路径和 96×96 热光；这不表示与独立火样张共用同一个渲染器实例。它没有新增岩石位图、外部模型或物理模拟。

预览默认选择陨石，在固定脚点观察岩壳滚动与火尾，可切换向左／向右；火势控件隐藏且禁用，组合内部使用固定火势。小尺寸为 `scale: 1`，石头约 50px；当前战斗使用 `scale: 1.85`、约 93 单位直径，两者尺寸由各自消费者决定。放大图仅便于观察。预览按时间增量和左右方向累计虚拟行程，切换方向不重算已有行程；重新落下或重新选择效果时重置观察时间与行程。这个原地展示不复现地形移动、4.5 秒结束、多颗并存或伤害流程。减少动态效果默认静止；用户明确点击播放后允许观察动画，保留低细节，与同页火、风行为一致。

## 卡尔混沌陨石接入契约

- 事件为 `castKaelSpell('chaos-meteor')`，被动随机与主动回响共用。先查找 `720 + 敌人半径` 内最近可直达目标，锁定朝向；按 `kaelSpellRank` 追加 1～3 颗至 `kaelMeteors`，不替换旧颗。主颗从角色位置向前最多 38 单位，近目标时缩短前移，额外两颗分别侧移 `-76`／`76` 后平行滚动；出生偏移也经过地形移动处理。伤害与资源规则见[卡尔技能设计](../characters/kael/技能设计.md)。
- 速度 160 单位／秒、地形碰撞半径 10；每颗寿命 4.5 秒，无阻挡行程仍为 720，每 0.3 秒在当前中心按 `88 + 敌人半径` 结算伤害，原始每次伤害系数不变，独立保存主动来源以应用主动强化。地形移动之后才更新表现数据：累计真实位移长度，并按水平运动正负决定 `travel` 的符号；无水平位移时沿用施放朝向的水平符号。`trailAngle` 只在实际位移非零时更新为该帧位移方向，阻挡时保留上次方向。传入渲染器的 `travel` 除以战斗尺度 `1.85`，使增大的岩石仍按实际行程滚动；阻挡或滑动不会被视觉行程绕过。
- 表现年龄依据本颗陨石的 `maxLife - life`（`maxLife: 4.5`），战斗尺度为 `1.85`；首 0.15 秒抬升量按 `72 * (1 - age / .15)²` 降至零，只表达下落，移动、寿命和伤害 tick 同时照常推进。首次伤害仍在累计 0.3 秒时发生，不增加落地伤害。正常渲染前 0.04 秒淡入、最后 0.12 秒淡出；火尾是跟随装饰，不是额外的持续伤害带。
- 像素主题按陨石地面 `y` 与角色、敌人、景物共同排序；初版在敌人之后、玩家之前绘制。危险区域与预警随后绘制，两主题都使用同一组合模块，旧像素地面橙色圆点已退出。
- 游戏页预加载并缓存一个陨石渲染器。未就绪或加载失败时绘制带橙色边缘的简化暗色岩石，保留真实位置与下落高度；失败记录警告，不阻断伤害或补播已结束的事件。正常效果与失败回退须分别验证。
- 普通战斗细节为 `.6`；减少动态效果时 `time` 固定为 `1.4`、`travel` 固定为 `0`、`lift` 为 `0`、细节为 `0`，内部火焰和石头转动停止，但地面位置仍随真实技能移动，火尾方向仍随实际运动更新。
- 暂停、波末和战败停止推进；波末／战败不会立即清除此状态，背景可能保留静止陨石。各颗寿命独立到期回收；下一波初始化清空数组，重开创建新对局，返回标题清除对局。实例列表由战斗循环拥有，渲染模块不管理生命周期；仍存在的陨石不阻塞下一次被动轮转。

旧构建已从真实入口验证陨石预览、桌面与触控模拟的自然被动、主动回响、暂停及两主题画面；移动横屏连续帧可见向右移动与岩壳转动。2026-10-15 的战斗尺寸、数量成长与并存规则更新后，实际验证以[游戏 README](../../README.md)新增记录为准，不能直接沿用旧构建结论。所有地形／遮挡组合、战斗资源失败回退、完整战斗减动效、逐次伤害计量、真实手机硬件及密集／长局性能仍需独立验收。

## 卡尔冰墙、EMP、炽魂与震荡波接线

这些效果仍由 `game.js` 的共用技能层程序绘制，没有新增独立元素模块或素材。冰墙在 `240 + 敌人半径` 内最近目标位置生成，命中线垂直于施法方向，全长 480、半长 240、半宽 36，冰块、冰堆、高光及等级细节同步覆盖该线；各道墙进入 `kaelIceWalls`，持续 10 秒，首个更新帧即伤害并减速，之后每 0.4 秒结算，原始每次伤害系数、35% 减速及每次命中刷新 0.55 秒减速保持不变，重复施法不覆盖旧墙。墙是伤害与减速区域，不作为地形阻挡。工作台 Kael 场景每 14 秒重置，便于观察冰墙与炽魂完整消退；受控预览仍不能替代自然对局验证。

EMP 以 `280 + 敌人半径` 内的实际敌人为施法条件，立即按 `22 + 技能伤害 × .65` 结算原始伤害并回复 12 法力；无目标不施放或返还法力。雷束加粗并持续 0.3 秒，命中爆炸半径 `max(42, 敌人半径 + 40)`，反馈延迟为 `.12 + min(目标序号, 6) × .012`，总寿命为该延迟加 `.9` 秒，开始后 `.24` 秒内展开、在 `.9` 秒内消退。雷束、扩张和残留均只反馈同一次即时命中，不追加伤害或回蓝。

炽魂每次固定两只，重复召唤替换旧对，寿命 12 秒、显示尺度 `1.3`、地形碰撞半径 11.7，攻击间隔 `.7` 秒、原始伤害 `10 + 技能伤害 × .3` 保持不变，攻击爪光 `.28` 秒。目标须同时位于炽魂 380 和玩家 440 内；离玩家超过 440 后进入回归，直到回到玩家 100 内。无目标或回归时，跟随锚点使用玩家世界坐标偏移 `(±42,+24)`，距锚点 18 内停止，移动经过真实地形处理；该偏移不随玩家朝向旋转。

震荡波先朝向 `300 + 敌人半径` 内最近有效敌人，再将每次施放独立追加到 `kaelBlasts`；保存固定原点、方向、施放时 `28 + 技能伤害 × .8` 原始伤害及主动来源。三道弧线分别延迟 0／`.14`／`.28` 秒开始，各在 `.72` 秒内推进至半径 300，总时长 1 秒；半角 `.95`，弧带全宽 12，判定容差为 `敌人半径 + width / 2`。仅在弧线前后帧半径实际扫过敌人时结算，三道弧线共用本次命中集合，每名敌人每次施放最多受伤与沿施法方向推离 70 一次；多次施放互不覆盖。`game.js` 拥有结算、数组与生命周期，基础绘制及 `hero-growth.js` 都消费 `waves.radius` 和 `waves.alpha`，减少动态效果也保留真实波前推进，绘制层不追加命中。两主题共用，暂停随对局时钟冻结，各实例到期回收，下一波与重开按对局清理规则重置；真实表现和命中覆盖以游戏 README 的本轮记录为准。
