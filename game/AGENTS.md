# DotaRogue Agent 入口

本入口只适用于 `game/`。新会话先读 `README.md`、`docs/core/协作上下文.md` 和 `docs/core/核心玩法.md`，再读任务相关的中文专题；涉及页面或操作时读 `docs/core/界面与交互.md`。设计文档是可回源的协作记忆，不代表目标功能已实现；当前行为仍要以 `static/dotarogue/index.html`、`static/dotarogue/css/game.css`、`static/dotarogue/js/game.js` 和真实页面核对。根目录 `AGENTS.md` 的公开、安全与发布边界仍适用。

- 保持游戏能从 `static/index.html` 进入，并能返回游戏选择页。后续游戏在 `static/` 下使用独立目录，不把不同游戏的状态或资源耦合到《DotaRogue》。游戏运行素材属于 `static/dotarogue/assets/`，设计与公开参考属于 `docs/`。来源清单、Concept／对照图、可编辑源与离线生成器归 `docs/sources/`；生成器默认写入 `static/dotarogue/assets/`，通过 `--output-root` 才另定输出目录，不在文档域保留重复运行帧。修改生成输入后核对正式输出、来源映射及真实消费者；不恢复旧页面路径或兼容跳转。
- 新增或修改成品装备及其成长前，先读 [新增武器工作流](docs/core/新增武器工作流.md)，通过 `nest-work-item` 定位或创建唯一工作项，再同步交付三级数值、现有被动与反馈、商店、HUD、暂停、三语言图鉴和验证记录；不能只做一级或只凭聊天记忆实施。
- 所有 `kind: "finished"` 成品都必须有固定合成配方，并支持三件同名同级免费合一，最高强化 Lv.3；防御、鞋类、吸血类也不排除。组件与中间件只参与固定配方，不参与三合一升阶。交付前逐项检查全部成品都有配方、全部成品集合与升阶配置集合完全一致，并验证属性／总卖价守恒及资源／冷却不刷新；具体方法与未覆盖范围记录按上述工作流执行。
- 游戏视觉不设必须原创的通用约束。角色可按 Warcraft III／DotA1 原型精确参考；直接引入外部资源前核对来源与使用许可，并在公开资料中如实标明来源。
- 新增、重画、打磨或审查游戏图像与动画（角色、怪物、场地、道具、技能特效、地图预览，含 `static/dotarogue/js/` 的 Canvas 绘制）时，开始这类任务前先读 [游戏作图方法论](docs/core/游戏作图方法论.md) 与 [视觉规范](docs/core/视觉规范.md)，再读对象相关专题；角色位图制作另读 [角色图片创作流程](docs/core/角色图片创作流程.md)。
- 改动输入、布局或战斗循环时，分别检查桌面键盘与鼠标、手机横竖屏触控；检查转屏、暂停、焦点、资源路径与浏览器控制台。实际未覆盖的波次或流程要明确说明。
- 变更本地记录格式时检查已有 `localStorage` 数据的读取与兼容性。实现或入口变化后更新本目录 `README.md`，把已实现能力和未来设想分开。
- 新增或修改设计决定时更新对应 `docs/core/` 专题与 `docs/core/协作上下文.md`；功能接入后才更新当前实现描述，并记录实际验证范围。
