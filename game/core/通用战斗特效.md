# 通用战斗特效

本专题是当前特效模块与消费者的事实入口。通用约束见[特效制作规范](特效制作规范.md)，研究、制作和验收步骤见[特效制作方法论](特效制作方法论.md)；下面的风、火、陨石参数各属于相应实例，不是所有特效的统一标准。

## Current：元素预览与卡尔的风、陨石

风已由[独立预览](../effects.html)和卡尔的混沌之风共同消费。预览控制器 [effects-preview.js](../../static/js/game/effects-preview.js) 负责调节与观察；战斗入口 [game.js](../../static/js/game/game.js) 负责真实事件。风使用同一弯曲漏斗、螺旋风带、碎叶与尘雾实现；新增陨石组合岩石与火模块，已接入卡尔混沌陨石，并成为第三种预览效果。火既用于独立样张，也由陨石间接用于战斗，独立样张本身不触发玩法。当前只接入卡尔一个英雄，其他英雄与装备未因此扩展。

源码与素材接入不代表浏览器视觉、真实手机或长局性能验收通过。实际验证范围记录在 [游戏 README](../README.md)，本专题只维护当前资源与调用契约。

## 目录与所有权

特效属于《DotaRogue》私有资源，不进入全站 `shared`。目前有真实消费者的模块为 `wind`、`fire` 与组合模块 `meteor`，不预建其他元素目录、统一注册表或通用引擎。

| 位置 | 责任与当前内容 |
| --- | --- |
| `static/js/game/effects/wind.js` | 风的素材加载、缓存、路径与 Canvas 绘制；不读取对局、角色或装备状态。 |
| `game/art/effects/wind/svg/` | 可编辑且直接消费的矢量素材：`leaf.svg` 碎叶、`wisp.svg` 气流片。 |
| `game/art/effects/wind/png/` | 直接消费的透明纹理：`dust.png`，128×128 RGBA 尘雾。 |
| `game/art/effects/wind/build_textures.py` | 离线重建尘雾纹理，依赖 Pillow；不是浏览器运行依赖。 |
| `static/js/game/effects/fire.js` | 程序化焰形、上升火星与余焰；工厂加载烟纹理并生成光晕缓存。 |
| `game/art/effects/fire/png/smoke.png` | 自制 128×128 RGBA 烟纹理，无 SVG 依赖。 |
| `game/art/effects/fire/build_textures.py` | 使用固定种子和 Pillow 离线重建烟纹理。 |
| `static/js/game/effects/meteor.js` | 原创岩石轮廓、岩壳裂缝、滚动与地面阴影，组合 `fire.js` 绘制包裹火焰和火尾；不新增陨石素材目录。 |
| `game/effects.html`、`static/css/game/effects.css`、`static/js/game/effects-preview.js` | 独立预览页、控件、衬底、尺寸和播放时钟。 |

SVG、PNG 从模块位置通过 `new URL('../../../game/art/effects/<元素>/…', import.meta.url)` 解析。单个工厂实例只解码／生成缓存一次；预览控制器缓存各元素的加载 Promise 和渲染器，重复切换复用该页缓存。失败清除对应缓存并提供重试，不禁止选择另一元素；过期的异步完成不覆盖当前选项。以上文件可作为静态资源交付，无运行时构建或外部特效服务。

需要修改尘雾形态时，调整 Python 生成器并在仓库根目录运行：

```text
python game/art/effects/wind/build_textures.py
python game/art/effects/fire/build_textures.py
```

生成器使用固定种子重建当前 PNG；SVG 直接编辑，风柱主体与运动曲线由 JavaScript 绘制。三者不是互相替代的三套方案。

## 风渲染器契约

稳定 ID 为 `wind`，入口为 [wind.js](../../static/js/game/effects/wind.js)：

```js
const wind = await createWindRenderer();
wind.draw(ctx, {
  x, y, time,
  scale: 1, intensity: 1, spin: 1, opacity: 1, detail: 1
});
```

- `ctx` 为 Canvas 2D 上下文；`x`、`y` 是当前坐标系中的风柱脚点，不是图片左上角。
- `time` 为调用者传入的秒数。渲染器没有独立时钟或每帧随机；相同参数重复绘制得到相同状态。调用者保持时间不变即可暂停，回到零可重新开始。
- `scale` 控制尺寸。默认风柱自脚点向上约 265 单位，外围尘雾另留空间；约 `0.34` 可观察 90px 高的风柱。预览页负责入场渐显与缩放，不由渲染器擅自结束效果。
- `intensity` 默认 `1`，内部限制在 `0.15–1.6`，改变宽度、流速及尘雾强度；小于等于零时不绘制。运行中改变风力会按新流速重算运动相位，可能出现短暂位置跳变；当前样张未做连续变速过渡。
- `spin` 以正负号选择相反旋向；`opacity` 为 `0–1`，并与调用者上下文透明度相乘。
- `detail` 为 `0–1`，上升粒子数从 36 调至 60，另有 12 个落脚尘雾；它不改变漏斗轮廓。

绘制保存并恢复上下文状态，不推进游戏时间，不修改玩家或敌人。螺旋路径采用有限采样，不使用每帧 `shadowBlur`。粒子数量上限与素材缓存是当前实现约束，**不是帧率或设备性能结论**。

战斗消费者决定事件触发、坐标、持续时间、冷却及结束清理；表现模块只负责绘制。改变脚点、时间单位、参数含义或素材路径时，须同步预览与战斗消费者、本专题及真实验证记录。

## 卡尔混沌之风接入契约

- 事件为 `castKaelSpell('tornado')`，被动万象轮转和主动回响使用同一分支。每次按 `kaelSpellRank` 生成 1～3 枚现有弹道，记录游戏时间 `startedAt` 与主动来源；主风对准 `774 + 敌人半径` 内最近有效敌人，额外两风分别偏转 `-.24`／`.24` 弧度，方向随后锁定，不追踪目标。
- `drawProjectiles()` 在通用弹道旋转变换前绘制，风柱始终直立，脚点与弹道世界坐标一致；相机与 DPR 由战斗画布负责，不在模块重复应用。旧的 500 单位紫色闪线已退出。
- 时间为 `run.totalTime - startedAt`，战斗尺度 `.56`（约 148 单位高），固定风力 1；前 0.06 秒淡入、最后 0.1 秒淡出，视口裁剪预留 170 单位以容纳风柱。独立元素预览的小尺寸仍约 90px。暂停不推进位移和内部运动；剩余寿命结束、穿透次数耗尽、出界或清空弹道时不再绘制。波末、重开和返回标题沿用原有生命周期，不保留独立风实例列表。
- 游戏页面预加载并缓存一个渲染器，离开对局仍复用该页缓存；素材尚未就绪或失败时沿用旧弹丸绘制，失败记录警告，不阻断战斗或补播已经结束的施法。
- 像素／初版共用此效果，局部图像平滑由模块恢复。普通细节为 50 个上升粒子与 12 个尘雾；减少动态效果时风柱仍按真实弹道移动，内部相位固定、粒子降至 36＋12。每次施法最多三实例，触发频率受 5 秒随机计时和基础 6 秒主动冷却限制，无新增同屏实例硬上限；未完成密集同屏性能测量。
- 2026-10-15 已同步调整玩法：速度 430 单位／秒、寿命 1.8 秒，最长行程约 774；扫掠命中半径 26，每风每敌一次、最多 8 次穿透、推离 34。伤害系数和原元素弹道地形规则保持，不新增吹起／悬空控制。数量只随 Kael 的“法术成长”升级从 1→2→3，装备法术攻击不触发数量增加；主动风的命中读取主动强化。

角色规则与反向资源登记见[卡尔技能设计](../characters/kael/技能设计.md)和[资源规划](../characters/kael/资源规划.md)。

## 火渲染器契约（独立预览与陨石组合）

稳定 ID 为 `fire`，入口为 [fire.js](../../static/js/game/effects/fire.js)：

```js
const fire = await createFireRenderer();
fire.draw(ctx, { x, y, time, scale: 1, intensity: 1, opacity: 1, detail: 1 });
```

`x/y` 是火焰脚点，`time` 是调用方提供的秒数；同参数绘制确定，无独立 RAF、每帧随机或对局读取。`scale` 缩放整体，`opacity` 与调用者 alpha 相乘，绘制后恢复上下文。主焰约 240 单位高，含烟火星保守预留约 280 高、220 宽，脚点下另留柔光空间。独立预览以 `90/240` 作为小尺寸缩放基准，实际高度随脉动与火势变化；这一尺寸不直接作为陨石或其他技能的战斗尺度。

`intensity` 内部限制为 `.6–1.4`，调整形态幅度与烟透明度，不乘进时间相位；小于等于零不绘制。火没有旋向参数。`detail` 在 `.7` 以下将烟／离焰／火星从 8／4／16 降至 4／2／8，保留主体 13 条焰路径；切换细节会改变烟相位分布，未提供连续细节过渡。有限预算不等于已测帧率。

主体采用橙红外焰、金黄中层、淡黄内焰；焰舌弯曲向上传播，弧形焰根收拢于脚点，烟在后层膨胀淡出，少量火星上升并缩小。全部使用 `source-over`，不依赖强加亮混合获得辨识度。独立预览负责入场、暂停、重播和包络留白，按当前元素隐藏无效旋向控件。火模块不拥有命中、伤害或结束判定；陨石组合的方向、尺度与生命周期由下节消费者提供，其他火技能仍需单独确认事件。

## 陨石渲染器与预览契约

稳定 ID 为 `meteor`，入口为 [meteor.js](../../static/js/game/effects/meteor.js)：

```js
const meteor = await createMeteorRenderer();
meteor.draw(ctx, {
  x, y, time, angle: 0, travel: 0, lift: 0,
  scale: 1, opacity: 1, detail: 1
});
```

- `x/y` 是地面锚点；默认石头主体直径约 50 单位，中心位于脚点上方 24 单位。`scale` 缩放石头和火尾，相机与 DPR 仍由调用方负责。
- `time` 为调用方传入的秒数，只驱动火焰、火星、烟和裂缝亮度。`travel` 是调用方累计提供的有符号行程，模块以 `travel / 24` 计算岩壳与裂缝转角，不自行按时间推算移动；战斗传真实位移，预览传虚拟观察行程。主体光照保持屏幕方向，不随裂缝转动。
- `angle` 为运动方向弧度，火尾朝其反方向展开。`lift` 为调用方坐标单位的非负抬升量，不随 `scale` 再次放大；阴影留在地面，石头中心为 `y - 24 * scale - lift`。
- `opacity` 限制在 `0–1` 并与调用方透明度相乘；`detail` 传给火模块，低于 `.7` 时岩面细节从 6 处减为 3 处。绘制保存并恢复 Canvas 状态，不修改玩法或推进时钟。

陨石工厂创建一个火渲染器，复用其实现与烟 PNG，另缓存岩石路径和 96×96 热光；这不表示与独立火样张共用同一个渲染器实例。它没有新增岩石位图、外部模型或物理模拟。

预览默认选择陨石，在固定脚点观察岩壳滚动与火尾，可切换向左／向右；火势控件隐藏且禁用，组合内部使用固定火势。小尺寸为 `scale: 1`，石头约 50px；当前战斗使用 `scale: 1.45`、约 73 单位直径，两者尺寸由各自消费者决定。放大图仅便于观察。预览按时间增量和左右方向累计虚拟行程，切换方向不重算已有行程；重新落下或重新选择效果时重置观察时间与行程。这个原地展示不复现地形移动、3 秒结束、多颗并存或伤害流程。减少动态效果默认静止；用户明确点击播放后允许观察动画，保留低细节，与同页火、风行为一致。

## 卡尔混沌陨石接入契约

- 事件为 `castKaelSpell('chaos-meteor')`，被动随机与主动回响共用。先查找 `720 + 敌人半径` 内最近可直达目标，锁定朝向；按 `kaelSpellRank` 追加 1～3 颗至 `kaelMeteors`，不替换旧颗。主颗从角色位置向前最多 38 单位，近目标时缩短前移，额外两颗分别侧移 `-76`／`76` 后平行滚动；出生偏移也经过地形移动处理。伤害与资源规则见[卡尔技能设计](../characters/kael/技能设计.md)。
- 速度 240 单位／秒、地形碰撞半径 10；每颗寿命 3 秒，每 0.3 秒在当前中心按 `68 + 敌人半径` 结算伤害，独立保存主动来源以应用主动强化。地形移动之后才更新表现数据：累计真实位移长度，并按水平运动正负决定 `travel` 的符号；无水平位移时沿用施放朝向的水平符号。`trailAngle` 只在实际位移非零时更新为该帧位移方向，阻挡时保留上次方向。传入渲染器的 `travel` 除以战斗尺度 `1.45`，使增大的岩石仍按实际行程滚动；阻挡或滑动不会被视觉行程绕过。
- 表现年龄为 `clamp(3 - life, 0, 3)`，战斗尺度为 `1.45`；首 0.15 秒抬升量按 `72 * (1 - age / .15)²` 降至零，只表达下落，移动、寿命和伤害 tick 同时照常推进。首次伤害仍在累计 0.3 秒时发生，不增加落地伤害。正常渲染前 0.04 秒淡入、最后 0.12 秒淡出；火尾是跟随装饰，不是额外的持续伤害带。
- 像素主题按陨石地面 `y` 与角色、敌人、景物共同排序；初版在敌人之后、玩家之前绘制。危险区域与预警随后绘制，两主题都使用同一组合模块，旧像素地面橙色圆点已退出。
- 游戏页预加载并缓存一个陨石渲染器。未就绪或加载失败时绘制带橙色边缘的简化暗色岩石，保留真实位置与下落高度；失败记录警告，不阻断伤害或补播已结束的事件。正常效果与失败回退须分别验证。
- 普通战斗细节为 `.6`；减少动态效果时 `time` 固定为 `1.4`、`travel` 固定为 `0`、`lift` 为 `0`、细节为 `0`，内部火焰和石头转动停止，但地面位置仍随真实技能移动，火尾方向仍随实际运动更新。
- 暂停、波末和战败停止推进；波末／战败不会立即清除此状态，背景可能保留静止陨石。各颗寿命独立到期回收；下一波初始化清空数组，重开创建新对局，返回标题清除对局。实例列表由战斗循环拥有，渲染模块不管理生命周期；仍存在的陨石不阻塞下一次被动轮转。

旧构建已从真实入口验证陨石预览、桌面与触控模拟的自然被动、主动回响、暂停及两主题画面；移动横屏连续帧可见向右移动与岩壳转动。2026-10-15 的战斗尺寸、数量成长与并存规则更新后，实际验证以[游戏 README](../README.md)新增记录为准，不能直接沿用旧构建结论。所有地形／遮挡组合、战斗资源失败回退、完整战斗减动效、逐次伤害计量、真实手机硬件及密集／长局性能仍需独立验收。

## 卡尔冰墙、EMP 与震荡波接线

这些效果仍由 `game.js` 的共用技能层程序绘制，没有新增独立元素模块或素材。冰墙在 `240 + 敌人半径` 内最近目标位置生成，命中线垂直于施法方向，全长 240、半宽 26，冰块、冰堆与高光同步覆盖该线；各道墙进入 `kaelIceWalls`，持续 6 秒，首个更新帧即伤害并减速，之后每 0.4 秒结算，重复施法不覆盖旧墙。墙是伤害与减速区域，不作为地形阻挡。

EMP 以 `190 + 敌人半径` 内的实际敌人为施法条件，并向受影响者绘制雷束和命中点爆炸；无目标不施放或返还法力。震荡波先朝向 `170 + 敌人半径` 内最近有效敌人，再绘制沿该方向推进的三道弧线并按前向弧带结算。可见层不附加额外伤害，两主题共用，暂停随对局时钟冻结；真实表现和命中覆盖以游戏 README 的本轮记录为准。
