# 游戏作图方法论

适用于角色、怪物、场地、道具、技能特效、动作和地图预览的设计、制作、接入与审查，包括图片素材和 Canvas 程序绘制。这是一套可复用的工作方法；其中的要求和示例不代表当前游戏已经全部做到。

本游戏的风格、素材 ID、尺寸和主题约定以[视觉规范.md](视觉规范.md)为准；地图布局与阻挡规则见[地图.md](地图.md)。角色位图的具体工具、异步任务和产物处理按[角色图片创作流程.md](角色图片创作流程.md)执行。这里不维护第二份素材清单或出图接口协议。

涉及元素、命中、弹道、持续场域或装备特效时，继续读取[特效制作规范](特效制作规范.md)和[特效制作方法论](特效制作方法论.md)。前者维护通用约束，后者维护专项制作步骤与模板；具体实现回源[通用战斗特效](通用战斗特效.md)，本文件不重复其正文。

## 先把目标写成看得见的结果

开始前读当前代码与素材，明确本轮对象、使用位置、实际显示尺寸、视角、脚点或锚点，以及需要表达的玩法信息。用户排除的对象保持在本轮范围之外；其他会话制作的素材先核对所有者，避免覆盖。

把“精致”“像参考游戏”拆成具体标准。例如：河道有连续圆弧和宽窄变化；水纹能看出流向；不同怪物在战斗尺寸下能凭剪影区分；草地、沙地和冻土有不同材质，同时敌人和危险提示仍清楚。先处理用户指出的缺陷，再补装饰。

参考作品时提炼轮廓、构图、比例、配色、明暗、材质和动作节奏。用户指定 WarCraft III／DotA1 原型时，可以按具体角色、武器、动作和特效精确参考；《Kingdom Rush》可以用来观察弯曲河岸、体积层次和小尺寸可读性。直接带入外部文件前核对来源与使用许可，并在公开资料中标明来源；没有明确授权的资源不进入仓库。

## 先定轮廓，再加细节

先完成一个低细节样张，在实际场景与实际尺寸下检查形状、比例和层次。轮廓通过后，再加主色、体积明暗、材质和局部装饰；先做一条河、一种地面或一个怪物，再扩展到其他地图与对象。

- 自然地形先设计整体走向、弯曲、宽窄和连接关系。矩形包围框用于定位与剔除，不直接充当天然河岸。圆角矩形、错位矩形拼接或增加鱼石，都不能替代连续的河道轮廓。
- 表达河流时先确定来向、去向与转弯；表达池塘时再使用封闭水面。河岸、浅滩与深水层沿同一形状建立，不把不同粗细的曲线简单叠成管道。
- 地面按“大块材质变化—局部纹理—少量装饰”建立层次，避免密集重复小图造成噪声。树与山石先有可辨体积，再加枝叶、裂纹和苔藓。
- 角色与怪物先看剪影、朝向和身份特征，再看眼睛、甲片等细节；相邻动作帧保持体型、配色与锚点稳定。

光源方向、投影和视角保持一致。地面细节与水面高光的对比度服从战斗主体，前景树冠与山石不能遮住血条、目的地、拾取物和危险提示。

## 绘制、碰撞与运动使用一致的几何

接入前明确哪些部分会阻挡、哪些只是装饰。素材脚点、绘制位置、碰撞中心和排序位置按同一约定对齐；河中装饰石头不因画得更大就自动成为障碍。

河流先定义中心线和宽度，再由一致的曲线求值或采样结果驱动岸线、水面裁剪、运动路径、碰撞和导航。仅共用控制点仍不足以证明一致：如果绘制用平滑曲线，碰撞却连接原始折线，弯道仍可能出现偏差。宽度变化和端点范围也要按实际轮廓核对。

岸沿可以作为视觉装饰外扩，但可走与不可走的边界必须清楚。实际检查贴岸移动、内外弯、两端、窄处、右键绕行和敌人追击，不能用“数据来自同一个对象”代替验证。

换皮按既有 ID 和锚点接入。纯美术变化保持玩法数值；用户明确授权改变地形轮廓时，才同步调整相应阻挡与导航，并回归受影响操作。

## 动态先表达行为，再调整强弱

动画要在真实战斗尺寸下肉眼可见，并表达对象的行为。水纹沿河道持续位移并随弯道改变方向；只闪烁透明度、只移动小鱼或只有静态水纹，都不能证明水在流动。

- 按路径长度安排运动位置，按切线决定方向；回到起点时用淡入淡出或屏外衔接，避免明显跳回。
- 水纹可以分布在不同流带并有少量速度差；岸线、河床和石头保持稳定。小鱼是补充细节，不代替水流本身。
- 怪物动作区分待机、移动、攻击、蓄力和受击，节奏与真实事件对应；画面主题或装饰动画不消耗战斗随机数。
- 战斗中的环境动画使用游戏时间，暂停后停止，恢复时不跳跃；速度与密度先以可辨为准，再避免抢占战斗注意力。

观察一段连续运行画面，用短录屏或间隔截图核对方向、速度与循环接缝。单张截图只能证明静态形状，不能证明流动、动作或暂停行为。

## 素材制作与接入分开记录

选择符合任务的素材路线：现有 SVG／Canvas 按原生格式修改；角色位图按已确认的图片创作流程制作，不把另一种制作方式冒充指定的出图结果。保留可编辑源图或生成原图，修改已有素材时保护其他会话的版本。

图片要检查真实透明通道、完整身体或物体、边缘残留和留白；在浅深背景上查看，并检查 128px／64px 预览及游戏实际显示尺寸。源图好看不等于缩小后可读；实际尺寸下看不见的细节应简化或放大。

分别记录“设计稿／提示词已写”“素材已生成”“素材已查看”“已接入”“真实流程已验证”。生成任务成功或文件下载成功不能替代图像查看；Concept 素材只有接入并完成相应验证后，才更新当前实现描述。

## 从真实画面验收和迭代

使用本轮源码与资源，从 `games.html` 进入《DotaRogue》，走到实际消费该素材的选择、战斗、暂停或其他受影响状态。按改动覆盖相关地图、主题、桌面和手机横竖屏；核对当前加载的资源，逐张查看截图。

先检查用户原始缺陷，再检查轮廓、材质、尺寸、动态、遮挡和交互。发现河流仍像水池或拼接块时回到轮廓层；流动不明显时回到运动层；贴岸移动不一致时回到几何层。不要靠增加细节掩盖这些问题。

交付说明改了什么，并分别列出自动检查、静态图像观察、动态观察与真实操作的结果及未覆盖范围。语法、差异、资源路径和控制台检查各自有价值，但不能替代视觉与端到端验证。文档规则接入成功也不代表新会话已实际遵守，需要在后续真实作图任务中核对读取和执行情况。
