# 新增武器工作流

本流程适用于《DotaRogue》所有 `kind: "finished"` 成品装备的新增、修改，以及为已有成品补齐成长；防御、鞋、吸血、物理或法术定位不改变适用性。先读 [游戏 README](../README.md)、[装备逐件设计](装备逐件设计.md)、[成品武器升阶设计](成品武器升阶设计.md)；涉及界面或绘图时，继续按 `game/AGENTS.md` 加载相应专题。源码与真实页面决定当前状态，设计方案不能代替已实现能力。

全部成品必须同时具有固定配方和 **Lv.1／Lv.2／Lv.3** 三档成长，保留三件同名同级合一、最高三级、属性和总卖价守恒的规则。只有组件和中间件不参与三合一；不能因“不是输出武器”而排除先锋盾、动力鞋、撒旦之邪力等成品。此规则已由用户明确确认，不由 Agent 自行缩小范围。只完成 Lv.1 时只能报告该阶段完成，不能称整件装备完整交付。

## 一个目标一个工作项

开始设计和修改前，使用本仓库的 [nest-work-item Skill](../../.agents/skills/nest-work-item/SKILL.md) 创建或定位一个可追踪目标。先按 Skill 的索引方法校验，在当前及归档项中按武器名称、成长目标查重，完整读取相似项 README 判断是否等价；命中等价项时沿用入口，不重复建项。创建路径按 Skill 返回已有入口后结束；任务还要求继续实施时，再进入继续工作项方法。无法唯一定位或索引校验失败时，按 Skill 保留现场并处理阻塞，不手编编号或覆盖索引。

新项的 ID、目录、根 README、原始需求、索引登记和写后校验均使用 Skill 当前方法与工具。独立新增一件武器对应一个目标，不为三个等级分别建项；同一授权任务批量补齐多件成品可共用一个工作项，但须逐件列出交付和验证范围。后续需求、方案、执行和测试事实使用 Skill 的更新路径回写。

## 执行顺序

1. **需求与边界。** 写明武器定位、近战／远程／技能适用性、成品分类、获取方式、配方及本次范围。确认名称与素材来源可公开；复用现有功能前核对当前源码，不引用旧武器槽草案推定行为。
2. **三档设计。** 一次列出 Lv.1／Lv.2／Lv.3 的可加属性、特色被动、触发资格与频率、目标数／范围／持续时间、同类取强规则、属性上限、成本／卖价和十二格制作路径。为每档写明对应特效、命中信息、两主题表现与动态效果预算；既有一级数值保持兼容，新增乘区要解释收益。没有新被动或分级战斗装饰时，明确保留现有行为并复用等级徽标与升阶反馈，不为凑等级虚构技能。方案未接线前标为目标。
3. **定义与战斗。** 在 `equipment.js` 的同一装备定义及 `EQUIPMENT_UPGRADES` 中接入三档，全部 `kind: "finished"` 的 ID 集合必须与 `EQUIPMENT_UPGRADES` 键集合完全一致，通过现有 `resolveEquipment`、出售和描述函数统一取值；在 `game.js` 接通战斗触发、配方和商店来源。沿用现有图标，新增物品才补齐对应图标及来源记录。不要复制三个独立装备定义，也不要让装饰特效改变伤害、触发次数或战斗随机数。
4. **完整界面。** 同步商店商品、固定配方、库存升阶／预览／出售、HUD、暂停及图鉴。简体、繁体、English 都要呈现强化等级、实际属性／被动和上限；图鉴保留三级对照、三合一资格和无 JavaScript 文字版。基础等级、合成阶段与强化 Lv. 分开，鼠标、键盘和手机都能完成操作。
5. **分层验证。** 先做语法、资源与有意义的数值逻辑检查：全量比较 finished 集合与升级表集合完全一致、逐件确认成品有有效且可从基础组件取得的固定配方，再检查三档成长、同级三合一、混级／不足／非适用／满级／重复点击／满格边界、属性／总卖价守恒、资源与冷却不刷新、同类被动取强及防递归。随后使用本次构建，从 `games.html` 真实进入，获得材料或成品、合成、升阶、带入战斗并核对最终效果；检查桌面键鼠、手机横竖屏触控、暂停／转屏／焦点、三语言、两主题、控制台、静态资源及无 JavaScript 可读性。界面改动按前端规则实际查看截图和计算样式。注入装备、固定随机数或直接调用函数只能记录为隔离检查，不能替代真实获取流程。
6. **记录交付。** 按工作项的需求／方案／执行／测试路径记录已发生事实，在 `game/README.md` 和对应装备、商店、界面、协作上下文专题更新当前能力与验证入口。列明实际武器、等级、波次、主题、语言、设备和证据；未取得的高阶、未到达的波次与平衡风险单列，不用其他武器或旧构建的验证代替。提交、推送和发布仍取决于当前任务授权。

## 完成检查表

- [ ] 已定位或创建唯一工作项，用户需求与本次范围可回源。
- [ ] 全部 finished ID 与 `EQUIPMENT_UPGRADES` 键完全一致，每件成品都有可达固定配方；组件和中间件均未获得三合一资格。
- [ ] 三档属性、被动、经济、特效已设计并同步接入；沿用现有行为和通用反馈的成品已如实说明，基础等级语义正确。
- [ ] 共享定义、战斗、素材、商店、HUD、暂停、三语言图鉴与无 JavaScript 说明一致。
- [ ] 数值逻辑检查、真实获取／升阶／战斗、布局与视觉检查分别记录，未覆盖内容明确。
- [ ] 工作项与游戏专题已按事实更新；只实现或验证部分等级时明确报告剩余范围。
