# 独立设计与预览

本文件维护 DotaRogue 五类内容的统一观察入口、正式数据所有权、运行复用与验收契约。具体英雄身份、装备数值、Buff 规则、特效参数及地图机制仍回源对应专题；本页不保存第二套内容定义。

## 当前状态

统一设计工作台当前可用，物理入口为 `game/studio.html`。已有 `game/effects.html` 的风、火和陨石样张继续可用；统一入口已完成接线和真实浏览器验收。受控场景仍不能证明自然对局已经获得物品或随机抽到技能。

英雄和地图定义已从现有 `game.js` 原文提取为 `js/game/heroes.js`、`js/game/maps.js`；仅调整模块导出与缩进，语法和文本一致性检查通过。运行导入、展示消费者及正常对局回归已完成当前范围验证。

## 所有权与真实消费者

以下是本阶段已采用并核对的接线决定；新增消费者或破坏性变更须按本契约补充核对。

| 内容 | 正式事实源 | 预览与游戏的关系 |
| --- | --- | --- |
| 英雄 | `js/game/heroes.js` 的英雄、普攻、主动配置、三语文案和卡尔六项当前法术；`game/characters/<id>/` 的设计与资源 | 工作台读取正式目录；动作与技能演示复用游戏当前行为和绘制。候选英雄或已暂停的历史法术不能因进入设计资料就标为可玩／当前。 |
| 武器／装备 | `js/game/equipment.js`；[新增武器工作流](新增武器工作流.md)及[成品武器升阶设计](成品武器升阶设计.md) | 预览读取同一装备与强化定义，演示对应真实触发；英雄自带攻击与成品装备身份分开。图鉴仍负责完整配方和三级说明。 |
| Buff | `js/game/buffs.js`；[Buff 设计](Buff设计.md) | 常规属性使用现有计算，受伤、周期等使用相应事件。纯属性 Buff 不虚构独立动画；预览不修改品质抽取规则。 |
| 特效 | `js/game/effects/`、`game/art/effects/`；[通用战斗特效](通用战斗特效.md) | 保留元素样张的独立观察语义；真实技能演示消费游戏事件及同一渲染器，不复制一份效果。 |
| 地图 | `js/game/maps.js` 的世界尺寸、地图与地形布局、曲线和 `buildTerrain`；[地图](地图.md) | 预览和游戏使用同一布局生成、绘制、碰撞与导航数据；不另画一张与实际地形无关的预览地图。 |

这些模块属于游戏内部，不上收到全站公共层，不为其他尚未实现的游戏预建注册表。常规游戏、统一工作台、元素样张和装备图鉴各自拥有界面与观察状态；共享内容的破坏性变更须同步当前消费者。

## 受控演示与正式游戏

工作台父页拥有分类、对象、动作选择和播放控件；嵌入同源 `game/index.html?studio=1`，由游戏内部的设计模式拥有演示局。两页用限定消息交互，父页不读取或任意改写游戏私有状态。当前消息协议为 `dotarogue-studio` → `dotarogue-runtime`：`init`、`select`、`play`、`replay`、`step`、`view`；运行页回传 `catalog`、`state`、`error`。字段由 `js/game/studio-runtime.js` 与工作台同源实现共同维护，父页只接收白名单目录和状态文本。

演示局复用正式初始化、技能、攻击、Buff／装备处理、时间更新与 Canvas 绘制，按当前选项布置有限目标及触发条件。它不推进正常敌潮、商店和战绩结算；重播或换对象时重建演示状态。播放、暂停、方向、主题是观察操作，不改变正式伤害、冷却和地形定义。

设计模式不写正常存档、设置或战绩。浏览器中的选择和播放不是仓库编辑器；正式修改由协作过程写入对应资源、配置或实现，重新加载消费者后使用同一结果。新增特殊行为仍需编码接线，不能由页面选择自动获得。

## 共同制作流程

1. 按对象读取现有专题及消费者，明确本次修改的是外观、参数还是玩法行为。
2. 在统一入口选择当前对象和适用动作，观察实际尺寸、方向、主题、暂停与连续运动；纯属性内容核对说明和属性结果。
3. 将已确认修改写入唯一正式事实源；不另存演示版数值或渲染实现。新增成品装备、角色和地图继续遵守各自完整交付规则。
4. 重新加载工作台，核对所改资源和代码确已加载，检查该对象及受影响的其他消费者。
5. 从 `games.html` 进入普通游戏，走真实选人、获取、施放、触发或通行链路，核对最终结果，分别记录预览与自然对局证据。
6. 把长期可复用经验和当前契约写回对应产品专题，把具体过程、失败、截图与未覆盖项写回工作项。

## 验证与状态边界

工作台是正式支持的设计预览功能，其真实入口与操作可以验收，但受控布置目标和触发场景不能证明自然对局已经获得物品或随机抽到技能。语法、定义一致性与资源检查也不能代替画面或实战。

状态按对象区分设计中、预览可用、游戏已接入、指定自然对局已验证。界面验收覆盖桌面、手机横竖屏模拟、键盘／触控、两主题、暂停恢复、减少动态效果、资源错误和无 JavaScript 基础说明；真实手机、全部组合和长局性能必须有独立证据。

前一构建已完成统一工作台实际接线与浏览器验收：8 英雄（当时含卡尔十法术变体）、38 装备、25 Buff、3 特效、3 地图；范围收缩后当前目录只保留卡尔六项法术，须以本轮构建复验六项的桌面／移动、键盘／触控、暂停／单步／重播和自然消费结果。真实手机硬件、Safari／Firefox、全部自然获取组合、密集同屏与长局性能仍未验证。四项暂停的历史法术不计入当前目录或验收矩阵。
