# 星核幸存者视觉规范

本文件维护本游戏的风格与素材约定；作图的步骤、几何与动态处理、迭代和验收按[游戏作图方法论.md](游戏作图方法论.md)执行。

## 主题现状

`../art/pixel/` 当前有 139 张 SVG，其中 34 张 `equipment-<装备 ID>.svg` 与 `../../js/game/equipment.js` 的 34 件装备逐件对应。其余文件包括八类敌人的 20 张基础／动作图、三张地图的 18 张地形与预览图，以及旧四角色的 12 张像素姿态图、16 张旧四技能图标和 4 张旧主动效果图。后面三组角色／技能旧图仍在目录中，但当前六英雄角色绘制与两技能栏不消费它们。六英雄新运行图位于各自 `../characters/<角色 ID>/art/runtime/`。两套主题共用六英雄运行图和 34 张装备图标；像素主题继续使用敌人与地图像素图，初版缺少对应图片时回退到 Canvas 图形或符号。两套主题共用玩法文字、地形布局和碰撞数据，切换不改变数值。

## 六名英雄的 Concept 首图与运行姿态

矮人火枪手、刚背兽、炼金术士、剑圣和影魔已有分别生成的手绘卡通待机 PNG；众神之王的四次 Lanox Image2 任务失败后，按用户后续决定另绘[运行 SVG](../characters/conductor/art/runtime/conductor-hero.svg)。角色原型的轮廓、比例与明暗分组可参考或精确对照 DotA1／War3 和 Kingdom Rush 的小尺寸表现，名称、种族与职业回源见[英雄.md](../../dota/英雄.md)及[角色设计包](../characters/README.md)。当前运行 SVG 是代码绘制的重绘资源，不是 AI PNG；后续若直接引入外部模型、贴图或动作文件，必须先核对来源与使用许可并记录。

五张 PNG 的原图、透明处理图和 128px／64px 缩图由各自 `art/concept/` 保存，继续作为造型 Concept 与制作来源。六名英雄各有前视 `<角色 ID>-hero.svg` 和右向侧身 `<角色 ID>-side.svg` 两张 2:3 分层 SVG 源图；源图不由战斗 Canvas 消费。每套源图生成 9 张无 SMIL 静态帧：`idle-a`、`idle-alt`、`walk-a`、`walk-b`、`dash`、`attack-windup`、`attack`、`attack-release`、`skill`，侧身文件在帧名前加 `side-`。`HERO_ART` 指向前视 `idle-a`；`HERO_POSE_ART` 指向前视其余 8 张和侧身 9 张。SVG 按角色原型和动作需求整理为可编辑路径，并非将单层 AI PNG 自动拆为骨骼；众神之王无 AI PNG，其 SVG 为独立绘制结果。

六张前视源图保留原有较丰富的身份细节，`build_pose_frames.py` 将近侧手臂、握手与基础武器联动，生成 54 张前视静态帧。另为每人绘制独立右向侧身源图；`build_side_pose_frames.py` 用肩、前臂、握手和武器的分层连接生成 54 张侧身静态帧。前视和侧身均保持头、躯干、脚点和武器的角色身份；侧身不是将前视整张图片旋转得到。

`game.js` 的两套主题均指向同一组六英雄姿态资源；Canvas 按图片原比例将每名角色绘为约 82～94 单位高，并以图片底部对齐脚点。静态 `idle-a` 与 `idle-alt` 按游戏时间交替，移动时交替 `walk-a`／`walk-b`，冲刺使用 `dash`，自动攻击按 `attack-windup` → `attack` → `attack-release` 三阶段切换，主动技能使用 `skill`；同时叠加身体起伏、轻微重心变化和打击反馈。移动、冲刺或攻击方向偏水平时选用独立右向侧身帧；朝左时镜像，其他角度使用前视帧。攻击命中事件落在出手阶段，远程角色另绘独立弹道，近战角色绘制职业基础武器和挥砍，技能姿态配合 Canvas 战场特效。暂停时游戏时间不前进，帧也保持不变。姿态帧在选定角色或开局时加载，缺失侧身帧时回退到前视帧；Canvas 的动作不依赖源图中的 SMIL。原有六英雄第一波、主题及手机视口短流程记录早于本轮侧身接入，不能代替新资源验收。本轮已逐帧检查前视与侧身静态拼版，并从带版本参数的 `games.html` 进入六名英雄各自第一波，在桌面实际 Canvas 观察前视待机、侧身移动和侧身攻击三阶段，Esc 暂停可用；炼金术士使用初版主题，其余五名使用像素风。独立 Chrome 移动触控环境的 390×844 与 844×390 短局已观察火枪手摇杆左右移动、侧身步行、左右镜像和攻击三阶段，未见水平溢出、页面错误或本地资源 4xx。其余五名英雄的新版手机动作、每人两主题完整矩阵、长局和真实手机硬件仍待核对。图片生成与清理的来源见[角色图片创作流程.md](角色图片创作流程.md)及各角色制作记录。

## 一键换皮的当前边界

`../../js/game/game.js` 通过 `selectedSkin` 为敌人、地图等对象选择像素风或初版资源；六英雄前视 `idle-a` 由 `HERO_ART` 提供，其余前视 8 帧和侧身 9 帧由 `HERO_POSE_ART` 提供，34 件装备图标固定从 `art/pixel/equipment-<装备 ID>.svg` 读取，均为两主题共用。标题、战斗 HUD 和暂停页提供画面切换按钮；切换只改变表现资源与界面样式，不改变角色、装备、属性、敌人行为、随机结果或当前对局。画面选择保存在已有浏览器设置中。初版缺少对应图片时沿用 Canvas 图形或文字图标。

当前运行素材覆盖六英雄、八类敌人、34 件装备图标、升级 `0`～`13` 图标，以及三张地图各自的地砖、树、石头、河流、陷阱和选择预览。升级池另有 `14`～`16` 三项，当前以文字符号回退。技能栏显示各英雄一主动、一被动的名称与状态；主动／被动的战场反馈由 Canvas 程序绘制，旧四技能图标和四张主动效果 SVG 不在当前映射中。材料、宝箱、弹丸和其他战斗特效仍有 Canvas 主题分支。后续增加主题时，须同时覆盖素材与程序绘制分支，再按真实状态逐屏检查。

换皮以当前素材映射为锚点：角色、敌人、地图与装备按玩法 ID 映射，已配图的升级按序号生成素材 ID。切换主题时保持对象位置、命中范围和数值不变。完整后续主题需覆盖正在使用的素材和拾取物、弹丸、技能场域、其他特效及界面的程序绘制；旧四技能与旧武器／改装存量图标无当前玩法消费者，不列为新主题的必备内容。初版只有原有少量样张，地图预览回退为符号，地形、陷阱与技能反馈回退为 Canvas 图形；音效不随画面切换。天赋尚未进入游戏，因此没有天赋图标或主题资产。

玩家角色当前有前视和独立右向侧身两套姿态；水平朝向使用侧身，向左镜像。朝其他角度移动或攻击时沿用前视，尚无独立向上、向下或背面源图与帧。子弹、斩击和技能特效仍按实际攻击方向绘制，两套画面遵守同一规则。局部姿态与程序化倾斜的质量须在真实战斗尺寸下连续观察；单张放大 SVG 不构成通过证据。

新增同一对象的主题素材时，保持其游戏 ID 与用途不变；同一主题内的基础图、动作帧和图标应共用轮廓特征及配色语义。动作帧缺失时先使用该对象基础图。新增装备、角色或敌人后，按实际消费位置补图并检查小尺寸可读性，不预建没有消费者的占位素材。

## 第一套风格：星港像素

- 方向是星港废土科幻。用厚轮廓、少量主色和清楚的明暗分组表达体积；32×32 的核心身份点必须在战斗缩放后可辨。
- 角色与友方装置以青绿、蓝灰和沙金分组；普通敌人使用锈橙、菌色等不同形体与危险色；精英和首领还靠体型、剪影与蓄力动作区分。
- 像素边缘应保持整数网格感。SVG 源图保留可编辑性，Canvas 使用 DPR backing store、整数网格尺寸，并在像素主题关闭场景像素图平滑、启用 `pixelated`/`crisp-edges`；六英雄 SVG 绘制时单独开启平滑。在标题选择、战斗和商店三个尺寸上核对，不只看放大的源图。近战基础攻击应有可辨认的刀身和挥砍方向。
- 后续补图遵循“玩法定位—原型或来源核对—黑白剪影—主色—动作帧—实机小尺寸检查”的顺序。观察《Kingdom Rush》的小尺寸可读性和动作反馈方法；需要时可按 War3／DotA1 原型精确复刻角色与动作，直接使用外部文件则先核对许可。当前三张地图使用沙地、草地、冻土、水流、树和山石；地面材质变化、圆弧河岸、沿中心线移动的水纹、河中石块、小鱼、分层岸沿和前景遮挡用于建立层次，河流视觉与胶囊碰撞使用同一份曲线数据。

## 后续主题：史诗奇幻

用户希望未来有一套受经典奇幻游戏氛围启发的主题，可从金属、布料、符文、魔法光效与职业辨识度提炼方向。它目前**没有素材或切换选项**。制作时可重绘，也可按 War3／DotA1 原型精确参考；若采用《魔兽世界》或其他作品的模型、贴图、图标与界面文件，先核对授权、来源和公开标注要求。

这是一套表现方向，不是第二套已经可玩的主题。《Kingdom Rush》可参考的是小尺寸轮廓、颜色分组和动作反馈；当前星港像素图使用清晰的整数色块，与它的手绘卡通画法不同。

新主题应先用一名角色、一种近战基础攻击、一种远程基础攻击、一件装备、一名普通敌人及一个技能做完整战斗样张，在实际缩放、碰撞和动态状态下通过 Review，再扩展到所有当前对象和界面状态。主题切换继续使用相同玩法 ID，避免为了美术差异改动战斗规则。

## 声音方向

声音反馈参考动作易辨的做法。当前浏览器用 Web Audio 的振荡器、扫频和短噪声原创合成声音：基础攻击、角色主动技、冲刺、受击、宝箱拾取与开箱、精英和首领预警有各自的音色；密集战斗音效有限流，设置中可以关闭。没有采样、截取、重制或引用 Dota、Warcraft 或其他游戏的音频与旋律。首版装备中的鹰角弓只加属性，不产生独立弓箭攻击，因此没有弓箭事件音效。

辨识度的设计顺序是起音、主体、收尾：远程射击用短促机械起音和低频主体，闪电用尖锐起音与颗粒噪声，挥砍用扫频和轻碰撞声，宝箱用上扬的两段提示。未来若设计真实弓箭攻击，再制作弦声、飞行气流与命中材质声；目前不生成没有事件触发的箭声。若未来希望声音也随画面主题变化，需要给同一事件配置另一套原创音色，再由画面选择切换。
