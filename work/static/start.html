什么是工作项

一件事的共同记录，
也是下一位的起点。

把“要做什么、按什么做、已经做到哪”放到可以读取的工作项中。换人或换 Agent 时，大家回到同一个目标继续。

01

为什么做

保留原始表达、需求、范围，以及什么样的结果才算做好。

目标与需求
02

按什么做

引用当前适用的方法，记录方案和已确认的取舍。

方法与决定
03

实际做了什么

留下动作、产物、检查结果、失败和还未验证的部分。

执行与证据
04

接下来做什么

明确当前停点、下一步和需要人决定的问题。

进度与交接

工作项记录当前事实，并指向实际材料和产物；接手者仍要读取相关正文和现场。

看一次交接

A 做到这里，
B 从这里接着做。

以“改善活动报名页”为例：A 和 B 使用不同的 Agent，围绕同一个工作项协作。展开每一步，看方法、记录和责任怎样接上。

Concept · 固定演示，未连接真实 Agent
01A 与 Agent X 建立工作项先查重，再按需求方法把目标说清楚
A：“手机上文字太挤，报名方式也不好找。请为这件事建立工作项。”

Agent X 先查找是否已有同目标的工作项；本示意中没有，于是读取已有页面，保存 A 的原话，整理需求、范围和完成标准。A 补充：“活动内容不要删。”

使用方法：先查重，保留来源，明确需求与完成标准。

写入 W-DEMO-024：目标、范围、A 的纠正
02A 与 Agent X 留下方案和停点按方案与当前适用方法，留下有效依据

Agent X 比较做法，整理出“先突出时间地点，再调整报名入口”的方案。A 确认方向，并明确暂不发布。

已确认保留活动内容；先不发布。

已完成需求与方案整理。

下一步按当前方案修改并检查手机页面。

未验证修改效果和实际使用体验。

更新同一工作项：当前方案、决定和下一步
03B 用 Agent Y 接手同一工作项先读当前依据，再按执行方法动手
B：“接手 W-DEMO-024，先读取当前需求、方案和停点，再按已授权的步骤继续。”

Agent Y 读取同一个工作项和当前页面，沿用已确认的要求。B 确认自己这一轮允许修改的范围，Agent Y 按当前步骤实施。

使用方法：恢复当前依据，按步骤执行，完成后回写。

接上 A 的决定和进度，记录 B 这一轮的实际动作
04B 与 Agent Y 验证并回写结果按验证方法，让下一次继续有依据

Agent Y 根据事前完成标准检查实际页面，把产物、检查结果和没有覆盖的部分写回 W-DEMO-024。人根据结果决定接受、纠正、调整、回退、继续或停止。

示例结果：“页面已调整，手机显示已检查；尚未发布，仍需活动负责人确认内容。”

使用方法：比较预期与实际，区分通过、失败和未验证。

同一工作项继续保留：成果、证据、新停点和待决定事项
W-DEMO-024

接手时，一起接过来的

  • 同一个目标容易找到时间、地点和报名方式
  • 当前适用的方法需求、方案、执行、验证与回写
  • 已经作出的决定保留内容，暂不发布
  • 真实进度与依据已完成什么、证据在哪、下一步是什么

可以换人、换 Agent，也可以由原来的人在另一个 Agent 中继续。

怎样按方法协作

方法论让人和 AI，
知道怎样把事做好。

方法明确每一步需要什么依据、怎样做、怎样判断结果，以及怎样交接。工作项引用适用方法，并留下应用这些方法后形成的决定和事实。

需求方法

把问题变成要求

人：说明需要，纠正理解，确认范围。

AI：读取资料，整理需求和完成标准。

留下：做什么，什么算做好
方案方法

把选择变成做法

人：参与影响目标的关键取舍。

AI：比较选择、代价和边界，形成方案。

留下：当前决定与执行依据
执行方法

按当前步骤推进

人：明确授权，补充或纠正要求。

AI：恢复依据，实施当前任务，写回实际结果。

留下：实际动作与当前停点
验证方法

用结果核对目标

人：根据成果和证据决定是否接受。

AI：按标准检查，说明偏差、失败和未验证。

留下：证据与下一步

人的纠正也要进入工作项。更新受影响的需求、方案和步骤，下一位人或 Agent 才能沿用新的理解。

按任务需要使用方法，可以迭代和返回；专业任务还要遵循对应领域的方法。

开始与接手

选择你的 Agent，
围绕同一个工作项开始。

让参与者都能读取工作项、适用方法和相关材料。推进一段后，把实际结果和停点写回来。

新工作
“为这个目标建立工作项，先保存原话，按需求方法整理目标和完成标准。”
接手工作
“继续这个工作项，先读当前依据和适用方法，再从当前停点推进。”

接手需要具备什么？

  • 参与者有权访问同一个工作项及其相关材料。
  • 使用的 Agent 能读取并遵循适用方法。
  • 当前方案、决定、停点和证据保持有效。
  • 这一轮的操作具备相应能力和授权。

这里展示协作方法与固定示意。跨工具访问、权限和执行需要实际接线；本页不提供自动交接服务。

从工作项继续长出来

有了工作项，
不同范围都有了可以汇总的事实。

工作项是最小可追踪的协作事实单元：目标、方法、决定、动作、产物、验证和当前停点都在这里留下。多个工作项关联起来，就能形成看板；经过人确认、真实场景验证并写清适用边界，也能沉淀为知识。

看板 · 按范围汇总CONCEPT

同一批工作项，看到不同层级的进展。

个人我有哪些进行中的事？

下一步、阻塞和待我决定什么

项目这一组工作项怎样交付？

依赖、里程碑和证据在哪里

组织哪些工作需要协调？

跨项目的重复目标、阻塞和取舍

企业哪些方向正在发生？

战略、能力建设和风险证据

这些是同一事实源的观察方式；看板按权限和范围汇总，不维护另一份状态。

知识库 · 从事实沉淀CONCEPT

做过的事，变成下一次可以回读的依据。

  1. 留下事实原始需求、决定、产物和验证结果可追溯。
  2. 建立关联把相似问题、方法和结果连起来。
  3. 整理复用从多个工作项归纳案例、方法和规范。
  4. 人来校验经过确认、场景验证和边界说明后再作为知识使用。

不是所有聊天都变成知识；知识库只接收有来源、经确认且可复用的结论。

工作项是底层事实单元。 看板回答“现在发生什么”，知识库回答“以后可以依据什么”；两者都应回到可读取、可验证的工作项记录。

这里是公开方向示意，不代表当前页面已经接通个人、项目、组织或企业看板，也不代表知识库会自动生成。
