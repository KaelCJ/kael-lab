01 · HUMAN–AGENT COLLABORATION

每一次正式协作，先绑定唯一工作项

工作项不是表格审批，也不是形式目录。它把人的原话、当前需求、方案、执行和证据放进同一个可恢复上下文，让新 Session 能继续而不是重新猜。

INTERACTIVE GUIDESTEP 01 / 05

创建或绑定工作项

先告诉 Agent 目标，并明确“创建工作项”。Agent 应先查现有项；同一目标已经存在时继续原编号，不重复建项。

可以直接这样说为“优化知识问答来源体验”创建工作项，先查重，再整理需求和验收标准。

创建目录不等于已获准修改产品、运行命令、提交或发布。

WORK ITEM ANATOMY

一个工作项里面有什么

顶层按职责拆分，不按阶段堆流水账。简单任务可以很短，复杂任务继续在所属目录细分。

入口README

当前简介与产物导航。它告诉后来者“这个目标是什么、从哪里继续”，不复制状态和完整正文。

需求 / SOURCE原始需求

保存用户原话、补充、纠正和事实来源。旧来源不因新理解而消失。

需求 / BASELINE当前需求

把来源整理成范围、REQ 与验收标准；明确做什么、不做什么、谁确认。

方案怎样满足

记录责任、取舍、代价、反例、影响和回退。方案获准不自动等于获准实施。

执行计划与实际

把方案拆成可暂停步骤，并如实记录真实动作、偏差、失败和恢复点。

测试 / 条件目录怎样证明

按对象选择静态检查、真实测试或人工确认；没有执行就明确写未执行。

产出给使用者的交付物

只放实际要使用、审阅或发布的内容。文件存在、内容完成、已发布是不同事实。

THREE WAYS TO CONTINUE

继续工作项的三种入口

  1. 从代办选择先查看进行中的工作项，再指定要继续的目标。查看当前代办，我要继续知识问答体验那个工作项。
  2. 先看代码现场当你只记得问题，不记得编号：先让 Agent 查看当前代码与改动，再匹配唯一工作项。先查看当前代码和工作树，判断这个问题属于哪个已有工作项；只分析，不修改。
  3. 手动指定编号知道编号时直接点名，最快也最准确。继续 R<编号>。先回读当前需求、方案和代码事实，再告诉我下一步。
AUTHORITY LAYERS

把动作授权说清楚

查看≠设计≠修改≠验证≠提交≠发布

“帮我看看”通常只授权只读分析；“直接做完并发布”才覆盖实现、检查和明确的外部发布动作。高影响或范围变化仍要停下来确认。

LIFECYCLE IS NOT ONE BUTTON

完成、归档、取消归档、删除

完成

目标当前闭环，代办状态结束。它不自动证明质量、发布或使用者验收。

归档

把闭环工作项可恢复地移出活动区。归档是移动，不是删除。

取消归档

同一个目标需要继续时恢复原工作项，不创建竞争编号。

删除

物理移除且可能难以恢复，必须单独明确授权和准确目标。

CURRENT · MANUAL
Session 承载太多内容时，手动调用 $nest-archive-check

它先检查本 Session 的事实是否已回写、工作项是否唯一、目录与引用是否冲突，再决定是否适合归档。它不是“清空上下文”按钮。

ROADMAP · AUTO CHECK

02 · VERTICAL KNOWLEDGE PRODUCT

Nest 知识库：先找到可靠材料，再让答案带着来源回来

它不是“把所有文档塞给模型”。目录负责发现，多文档标签负责对照，问答负责缩短检索路径，来源负责让人判断答案是否可靠。

INTERACTIVE GUIDESTEP 01 / 06

浏览主题与目录

从领域主题进入目录，观察文档标题、层级和最近上下文。还没形成问题时，先浏览比直接问“大而全”的问题更稳。

示例问题我在异步执行中丢失了上下文，应该先核对哪些机制和边界？

目录命中只能证明材料存在，不能证明它适用于你的版本和现场。

ASK WITH CONTEXT

一个可回答的问题长什么样

场景＋观察到的现象＋已经核对的内容＋期望结果

例如：“消息消费切到线程池后 Trace 断了；主线程能看到上下文，子线程看不到；已核对入口拦截；应该先检查传播还是存储？”

SOURCE BEFORE CONFIDENCE

答案之后必须看什么

  • 来源文档是不是当前版本或当前主题
  • 引用片段是否真的支持答案，而非只包含相似词
  • 结论是事实、经验建议还是条件化推断
  • 是否明确了不适用场景和仍需核对的现场
CURRENT BOUNDARY

没有可靠答案时，正确结果是暴露缺口

知识库应明确“现有来源不足”“版本不明”或“需要查看代码/运行现场”，并给出下一步核对方向。生成一段流畅文字不能替代可靠证据。

03 · GENERAL AGENT EXECUTION PRODUCT

Codex Workbench：把一次执行变成可观察的 Session

Workbench 不重做 Coding Agent。它提供工作目录、Session、Thread、Turn、流式事件与本机历史的产品入口，让人看得见执行正在发生什么。

INTERACTIVE GUIDESTEP 01 / 07

输入绝对工作目录

工作目录决定 Agent 能看到哪个项目现场。使用操作系统绝对路径，并在启动前确认它就是本轮要处理的仓库。

Turn 示例先读取项目入口并查看当前工作树，只报告与当前目标相关的事实，不修改文件。

帮助页不会读取本机目录，也不会真实启动 Session。

CURRENT

当前运行边界

  • 一个 Session 管理一个子进程
  • Session 内可创建或继续 Thread
  • Turn 事件以流式方式进入工作台
  • 当前运行策略是 read-only
  • 审批策略是 approval never
  • 可查看本机已有历史
NOT SUPPORTED / NOT VERIFIED

不要从界面推断这些能力

  • 文件写入与受控审批尚未支持或未验证
  • 自动重连与进程恢复尚未支持或未验证
  • Thread fork、archive、delete 尚未支持或未验证
  • 多人协作、云 Workspace 与用量计费属于 Roadmap
